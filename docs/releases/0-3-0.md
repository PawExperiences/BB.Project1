# e2e prime tester 0.3.0 (0.3.0)

## e2e prime tester 0.3.0

This is the **initial release** of the *e2e prime tester* project. It ships a self-contained C++17 console application (`prime_tester`) that determines whether integers are prime using a fast, dependency-free trial-division algorithm with the 6k±1 optimisation. Numbers can be supplied as command-line arguments or piped via stdin; valid results go to stdout, invalid tokens are reported on stderr, and the exit code reliably signals success or failure. The release also includes complete build instructions and a worked-examples table in the README, a contributor guide, a release checklist, and the full suite of CI and release helper scripts so the project is immediately operable end-to-end.

### Highlights
- **`prime_tester` binary**: C++17, zero dependencies — just CMake 3.16+ and a C++ compiler.
- **Dual input modes**: pass numbers as argv tokens or pipe them line-by-line from stdin.
- **Robust error handling**: invalid/overflow tokens printed to stderr; exit code 1 on any error.
- **Fully documented**: README with exact build commands and an 8-row worked-examples table.
- **CI-ready**: `.github/workflows/build.yml` scaffolded and current with the toolchain.
- **Release tooling**: idempotent release and run scripts in Python, sh, and PowerShell.

# Changelog

## [0.3.0] – 2025 (Initial Release)

### Added
- **Prime Tester Console App** (`prime_tester`): C++17 self-contained executable that determines whether integers are prime using a trial-division algorithm with the 6k±1 optimisation. Accepts input via command-line arguments or stdin. Outputs `<n> is prime` / `<n> is not prime` to stdout; invalid tokens reported on stderr with exit code 1.
- **`src/prime.h`**: Public header declaring `bool is_prime(long long n)`.
- **`src/prime.cpp`**: Trial-division implementation with 6k±1 optimisation, handling edge cases for n < 2, n = 2, n = 3, even numbers, and multiples of 3. Safe for `LLONG_MAX`.
- **`src/main.cpp`**: Entry point with dual-mode input (argv or stdin), full error handling, and correct exit codes.
- **`CMakeLists.txt`**: CMake 3.16 build definition for target `prime_tester` (src/main.cpp + src/prime.cpp only; sieve files excluded).
- **`README.md`**: Project readme with build instructions (`cmake -B build` / `cmake --build build`) and a worked-examples table covering 8 test cases (prime, composite, 0, 1, negative, non-numeric, empty stdin, `--upto` range mode).
- **`src/sieve.cpp` / `src/sieve.h`**: Sieve-of-Eratosthenes implementation for range queries (bundled from sibling sieve task present in repo).
- **`CHANGELOG.md`**: Project-level changelog file.
- **`CONTRIBUTING.md`**: Contributor guide aligned with the project changelog and workflow.
- **`RELEASING.md`**: Release checklist for maintainers.
- **`docs/releases/0-3-0.md`**: Detailed release notes document for this release.
- **`release/scripts/release.{py,sh,ps1}`**: Automated release helper scripts (tag, publish, upload artifact).
- **`release/scripts/run.{py,sh,ps1}`**: App launch helper scripts.
- **`.github/workflows/build.yml`**: CI build workflow (BuildBoard-managed) updated to build the C++ project.

If any of these have drifted, update the BuildBoard build resource config so the workflow re-scaffolds before proceeding. This step is mandatory per CI workflow currency policy.
2. [manual] Ensure the release branch / commit is green on CI - Navigate to https://github.com/PawExperiences/BB.Project1/actions and confirm the latest build workflow run on the release commit is passing (green). Do not proceed if the build is red or pending.
3. [automated] Check out the release commit locally - git fetch origin && git checkout b6a5b27
(or the merge commit of PR #107 if a later merge SHA exists — verify with `git log --oneline -5`).
4. [automated] Build the release artifact locally to verify - Run from the repo root:
  cmake -B build -DCMAKE_BUILD_TYPE=Release
  cmake --build build --config Release
Expected: executable at `build/prime_tester` (Linux/macOS) or `build/Release/prime_tester.exe` (Windows) with zero compiler warnings.
5. [automated] Run smoke tests against the built binary - Execute the following and verify outputs exactly:
  ./build/prime_tester 2 3 4        # stdout: '2 is prime', '3 is prime', '4 is not prime'; exit 0
  echo -e '7\n9' | ./build/prime_tester  # stdout: '7 is prime', '9 is not prime'; exit 0
  ./build/prime_tester abc           # stderr: 'not a number: abc'; exit 1
  ./build/prime_tester 5 bad 7       # stdout lines for 5 and 7, stderr for bad; exit 1
  echo -n '' | ./build/prime_tester  # no output; exit 0
6. [automated] Create and push the release tag v0.3.0 - Run the release script (see scripts section):

7. [manual] Verify GitHub Release draft and publish - Open https://github.com/PawExperiences/BB.Project1/releases and find the draft release `v0.3.0`. Confirm: tag is `v0.3.0`, release body matches the changelog, and the `prime_tester` binary is attached as an asset. Click 'Publish release' to make it public.

[manual] Update CHANGELOG.md if not already committed - Confirm that `CHANGELOG.md` in the repo contains the 0.3.0 entry (it was committed in the bundled commits — verify with `git show HEAD:CHANGELOG.md`). ## Rollback

1. This is the initial release (no previous tag exists), so a rollback means removing the release artefact and tag from GitHub — but per protected-remote-state rules, deleting tags or releases remotely is forbidden and must be performed by a human with repository admin rights.
2. To stop serving the binary: pull the previous commit (pre-release HEAD) and rebuild locally: `git checkout <pre-release-sha> && cmake -B build && cmake --build build`.
3. To revert the CI workflow to a non-building state: open a PR that reverts `.github/workflows/build.yml` to its pre-0.3.0 content — do NOT force-push or delete the workflow file.
4. If the GitHub Release page must be retracted, a human admin should mark it as a draft or delete it via the GitHub UI; the Releaser agent does not perform this action.
5. No database migrations were applied, so no data rollback is required.
