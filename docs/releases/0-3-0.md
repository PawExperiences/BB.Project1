# e2e prime tester 0.3.0 (0.3.0)

## e2e prime tester 0.3.0

This is the **initial release** of the e2e prime tester — a focused C++ command-line tool for primality testing and prime-range enumeration via the Sieve of Eratosthenes. The project is built with CMake and ships with platform-independent helper scripts for building, running, and releasing on Linux, macOS, and Windows.

### Highlights
- A clean, fast primality tester written in C++ (`src/prime.cpp`) callable from the console.
- A Sieve of Eratosthenes implementation (`src/sieve.cpp`) that generates all primes in a given range, with an integrated benchmark so you can measure throughput on your hardware.
- Full CMake project (`CMakeLists.txt`) for portable, out-of-source builds.
- Detailed manual verification steps added to the README so contributors and reviewers can confirm correct output without automation.
- Release and run helper scripts provided in Python, Bash, and PowerShell for every major OS.
- CI build workflow updated to track the CMake toolchain used by this release.

> **Note:** This repository also contains Space Invaders JavaScript files from a co-hosted project. Those files are unrelated to the prime tester and are excluded from this release's scope.

## Release steps

1. [manual] Confirm CI build is green on main - Open the Actions tab on https://github.com/PawExperiences/BB.Project1 and verify the latest run of `.github/workflows/build.yml` on the `main` branch passed. Do not proceed if CI is red.
2. [manual] Verify CI workflow currency against this release's toolchain - Open `.github/workflows/build.yml` and confirm: (a) the build command matches `cmake -B build -S . && cmake --build build` (or whatever CMakeLists.txt top-level target produces the prime-tester binary), (b) the artifact path points to the actual binary output directory (e.g., `build/`). If either differs from what CMakeLists.txt produces, update the BuildBoard build resource config so the workflow re-scaffolds before tagging. This step is REQUIRED — CI must never drift from what the project actually builds.
3. [manual] Run local build and smoke test - Execute: `cmake -B build -S . -DCMAKE_BUILD_TYPE=Release && cmake --build build --config Release`. Then run the binary with a handful of known primes and composites to confirm correct output. Also run the sieve benchmark to confirm it exits cleanly.
4. [automated] Create and push the release tag v0.3.0 - Run: `git tag -a v0.3.0 -m 'Release e2e prime tester 0.3.0' && git push origin v0.3.0`. This is performed by `release/scripts/release.{py,sh,ps1}`. The tag must point to the tip of `main` after all release commits (including 2c484dd) are merged.
5. [automated] Build release artifact - CI will trigger on the pushed tag and produce the compiled binary. If CI does not auto-trigger on tags, build locally with `cmake -B build -S . -DCMAKE_BUILD_TYPE=Release && cmake --build build --config Release` and collect the binary from the `build/` directory.
6. [automated] Create GitHub release for v0.3.0 - Using the GitHub CLI: `gh release create v0.3.0 --title 'e2e prime tester 0.3.0' --notes-file docs/releases/0-3-0.md build/<prime-tester-binary>`. Replace `<prime-tester-binary>` with the actual binary name produced by CMake. The release/scripts/release.{py,sh,ps1} scripts handle this step.
7. [manual] Verify the published GitHub release - Navigate to https://github.com/PawExperiences/BB.Project1/releases/tag/v0.3.0 and confirm: (a) release title is correct, (b) release notes render correctly, (c) the binary artifact is attached and downloadable, (d) the release is not marked as a pre-release (unless intended).
8. [manual] Announce the release - Notify relevant stakeholders (team channel, mailing list, or project board) that e2e prime tester 0.3.0 is live, linking to the GitHub release page.

Inform users via release notes that 0.3.0 has been retracted and point them to the repository's main branch for status. \n4. If a binary artifact was uploaded and contains a critical defect, remove it from the GitHub release assets and replace with a corrected build under a 0.3.1 patch release. \n5. No database or schema changes were made, so there is no data rollback required.
