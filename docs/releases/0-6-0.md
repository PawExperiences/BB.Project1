# e2e prime tester cc 0.6.0 (0.6.0)

## prime_tester v0.6.0

First release of `prime_tester`, a small, dependency-free C++17 command-line tool for checking primality. Feed it integers as arguments or pipe them in one per line on stdin, and it reports which are prime; pass `--upto N` and it lists every prime up to N using a Sieve of Eratosthenes. No install step, no third-party dependencies, no test framework -- just CMake and a compiler.

### Highlights
- Check individual numbers: `prime_tester 2 3 4 17 18`
- Or pipe a list in: `printf '2\n4\n17\n' | prime_tester`
- List a whole range: `prime_tester --upto 30`
- Bad input doesn't stop the run: malformed tokens are reported on stderr as `not a number: <token>` and processing continues, with a non-zero exit status once done
- Built on a single reusable primality check (`is_prime`, trial division with the 6k+/-1 optimisation) plus a dedicated `primes_up_to` sieve for ranges -- the sieve is additive and does not change the existing single-number check
- README documents the exact build commands and a full 8-case manual-verification table

See CHANGELOG.md for the itemised list of changes.

# Changelog

## [0.6.0] - 2026-08-11

### Added
- `prime_tester`: a C++17 CLI that reports primality for integers passed as command-line arguments, or read one per line from stdin when no arguments are given. Prints `<n> is prime` / `<n> is not prime` per value. (#201)
- `is_prime(long long n)` in `src/prime.h` / `src/prime.cpp`: trial division up to sqrt(n) with the classic 6k+/-1 skip, used by the CLI and reusable as a library function. (#201)
- Error handling: a malformed token (not an integer, or out of `long long` range), from either argv or stdin, is reported to stderr as `not a number: <token>`; the run continues processing remaining input and exits with status 1 once done. A run with no bad tokens exits 0; empty stdin is a valid, silent, zero-exit run. (#201)
- `--upto N` mode: prints every prime from 2 up to N inclusive, one per line, in ascending order; N < 2 prints nothing and exits 0. (#202)
- `primes_up_to(long long n)` in `src/sieve.h` / `src/sieve.cpp`: a Sieve-of-Eratosthenes range sieve, kept separate from and not replacing the single-number `is_prime` check. (#202)
- Root `CMakeLists.txt` (CMake >=3.16, C++17) building a single `prime_tester` executable from `src/main.cpp`, `src/prime.cpp`, and `src/sieve.cpp`, with no third-party dependencies, no test framework, and no install step. (#201, #202)
- `README.md`: exact build/run commands (`cmake -B build`, `cmake --build build`) and an 8-row manual-verification table (prime, composite, 0, 1, negative, non-numeric token, empty stdin, `--upto 30`) with verbatim expected stdout and exit status for each. (#203)

## Rollback

This is the project's first release (PREVIOUS: None) -- there is no prior version to roll back to. If v0.6.0 is found broken after publishing:
1. Do not delete the v0.6.0 git tag, the GitHub release, or its uploaded binary -- deleting remote state is forbidden. Instead edit the GitHub release in place: mark it as a pre-release and prepend a short warning line to the release notes body pointing at the incoming fix.
2. Cut a corrective v0.6.1 through this same runbook as soon as the fix is groomed and Done, so users have a known-good tag to move to.
3. If the break is severe (e.g. the artifact does not run at all), open a new GitHub issue documenting the defect and the incoming fix version -- additive only, nothing existing is touched.
4. prime_tester has no server component, no database, and no migrations, so rollback carries no data-loss or downtime risk -- it is purely 'stop recommending this artifact, ship a corrected one'.
