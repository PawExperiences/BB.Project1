# e2e calculator cc 0.4.0

First shippable release of the e2e calculator: a small, dependency-free Swing desktop calculator backed by a hand-built arithmetic expression evaluator. Type or click an expression — digits, `+ - * /`, parentheses, decimals — and press `=` or Enter to evaluate; invalid input shows a clear error instead of crashing. Ships as a single runnable jar with no external runtime dependencies.

## Highlights
- Full expression evaluator: `+ - * /` with correct precedence, arbitrarily nested parentheses, decimals, and both leading and post-operator unary minus.
- Division-by-zero and malformed expressions (unbalanced parens, empty input, bad syntax) always surface a named error message — never a crash, `NaN`, or `Infinity`.
- Point-and-click or keyboard-only operation: every button has a keyboard equivalent, including Enter for `=`, Escape for `C`, and Backspace to delete.
- Built test-first end to end (`SkeletonTest`, `EvaluatorTest`, `CalculatorWindowTest`) per this project's TDD flavour.
- Zero runtime dependencies — a single `java -jar calculator-0.1.0.jar` is all you need.

## Get it
- Download `calculator-0.1.0.jar` from this release's assets.
- Run: `java -jar calculator-0.1.0.jar` (Java 21+ required).

## Rollback

This is the first tagged release, so there is no earlier version for users to fall back to — 'rollback' means undoing v0.4.0 forward, not reverting to a prior one, and it must stay additive (no deleting the v0.4.0 tag, GitHub release, or any commit history).

1. Do NOT delete or force-push the v0.4.0 tag or the GitHub release — that is forbidden remote-state destruction and would orphan anyone who already downloaded calculator-0.1.0.jar.
2. If a defect is found, revert the offending commit(s) on the default branch with `git revert` (never `git reset --hard` or history rewrite), fix forward, and cut a new patch release (e.g. 0.4.1) through the same release/scripts/release.* script.
3. Edit the existing v0.4.0 GitHub release description in place (not delete it) to add a visible warning banner pointing at the corrected release once 0.4.1 is published.
4. If the jar is actively harmful to run, ask a human to mark the v0.4.0 GitHub release as a 'pre-release' (an in-place edit, not a deletion) to reduce its visibility as 'Latest', and set 0.4.1 as Latest once published.
5. No data/schema migrations exist in this release, so there is nothing to reverse on the data side.
