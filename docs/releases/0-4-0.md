# e2e calculator cc 0.4.0 (0.4.0)

## e2e calculator cc 0.4.0

The first release of the e2e calculator: a small, dependency-free Java 21 + Swing desktop calculator, built test-first end to end. Build once with Maven and run anywhere with a single `java -jar` command -- no external classpath, no runtime dependencies.

### Highlights
- **Four-function arithmetic engine** (`Evaluator`) with correct operator precedence, arbitrarily nested parentheses, decimals, and unary minus, unit-tested ahead of the implementation (TDD red/green).
- **Safe error handling**: divide-by-zero and malformed expressions raise a `CalculationException` with a specific message instead of ever silently returning `NaN` or `Infinity`.
- **Swing desktop UI** (`CalculatorWindow`): a 320x420 window with a button grid and full keyboard support (digits, operators, Enter, Escape, Backspace).
- **Single executable JAR**: `mvn -B package` produces `target/calculator-0.1.0.jar`, launchable with `java -jar target/calculator-0.1.0.jar`.

### Get it
```
mvn -B package
java -jar target/calculator-0.1.0.jar
```

### Notes
- No data/schema migrations in this release.
- No breaking changes -- this is the initial release.

### Added
- Maven project skeleton targeting Java 21 with JUnit 5.10.2 + Surefire 3.2.5, so `mvn -B test` runs green from an empty project (#192).
- `Evaluator.evaluate(String)`: a UI-independent four-function arithmetic engine with correct `*`/`/` over `+`/`-` precedence, arbitrarily nested parentheses, decimal literals, and unary minus (leading and post-operator); whitespace is insignificant (#193).
- `CalculationException`: a checked exception thrown for division by zero and malformed input (unbalanced parentheses, empty string, etc.) so `evaluate()` never returns `NaN`/`Infinity` (#193).
- `CalculatorWindow`: a Swing `JFrame` ("Calculator", 320x420 minimum) with a non-editable right-aligned display, a `GridBagLayout` button grid (digits, `.`, `+ - * /`, `(` `)`, `C`, `=`), and full keyboard mirroring (digits/operators, Enter=`=`, Escape=`C`, Backspace) (#194).
- `Main`: application entry point that launches `CalculatorWindow` on the Swing EDT via `SwingUtilities.invokeLater` (#195).
- `maven-jar-plugin` configuration producing a self-contained, directly runnable `target/calculator-0.1.0.jar` (`Main-Class: com.buildboard.calculator.Main`); no shade/assembly plugin needed since there are no runtime dependencies (#195).

This is the first release (no prior tag to compare against), so 'rollback' means withdrawing v0.4.0 from use without deleting any remote history, tags, or releases (deleting remote state is forbidden for this role).

1. Do not delete the v0.4.0 tag or GitHub release. Instead, mark the GitHub release as a pre-release (Edit release -> check 'Set as a pre-release') so it stops surfacing as 'Latest', and add a note at the top of the release body warning users to hold off.
2. There is no earlier known-good JAR to fall back to (this is the first release) -- instruct users to stop using the v0.4.0 jar until a fix ships.
3. Cut a forward-fix release (e.g. v0.4.1) once the defect is corrected. Always fix-forward; never rewrite or force-push the v0.4.0 tag or commit.
4. The app is a standalone desktop JAR with no server component and no data/schema migrations, so there is no running service to fail over and no database state to revert -- rollback here is purely a distribution/communication action.
