# e2e infra plan 0.1.0 (0.1.0)

## e2e infra plan 0.1.0

This is the first release of **e2e infra plan**: a minimal, cloud-free Terraform configuration that proves out BuildBoard's plan-only Terraform pipeline end-to-end. It generates a random pet name, plans to write it to a local file, centralizes name-normalization logic in a reusable `modules/naming` module, and ships fully documented and validated — `terraform fmt -check` and `terraform validate` both pass clean, and `README.md` carries terraform-docs-generated Inputs/Outputs tables. No cloud provider, credentials, backend, or state file is involved anywhere in this release.

### Highlights
- Cloud-free root config using only the `random` and `local` providers — `terraform init` and `terraform plan` both succeed with zero credentials and zero backend config, reporting 2 resources to add.
- New `modules/naming` module: normalizes `prefix` + `environment` into one lowercase, hyphen-joined name, exposed as `module.naming.name`.
- Root configuration refactored to consume `module.naming.name` instead of inline string concatenation.
- `.terraform-docs.yml` drives generated Inputs/Outputs tables in `README.md`, alongside the exact `terraform plan` command to run.
- `README.md` states plainly that BuildBoard's pipeline only ever plans — it never applies.
- `terraform fmt -check -recursive` and `terraform validate` both pass with zero pending changes.

## Rollback

No cloud resources are ever created — BuildBoard's pipeline only runs `terraform plan`, never `terraform apply` — so there is no live infrastructure state to roll back and no .tfstate file exists anywhere in the repo. If v0.1.0 needs to be retracted: (1) do not delete the GitHub tag or release (destructive remote actions are forbidden) — instead edit the GitHub Release to mark it as a pre-release/draft with a note pointing back to the prior state; (2) open a new PR that `git revert`s the merge commits for the bundled tasks (a82ec5e, 7dcab93, and the module task's commit once its existence is confirmed) on `main` — never force-push or rewrite history; (3) re-run `terraform init -input=false && terraform validate && terraform plan -input=false` on the reverted tree and confirm it still plans clean; (4) cut a new patch tag (e.g. v0.1.1) documenting the revert, since v0.1.0 itself is never deleted.
