# e2e cli greeter 0.1.0 (0.1.0)

## e2e cli greeter 0.1.0

First release of the e2e CLI greeter: a minimal, dependency-free Node.js command-line tool that greets one or more names, shipped with a self-check script and full usage documentation.

### Highlights
- `node greet.js` prints `Hello, world!` with no arguments, `Hello, Alice!` for one name, and `Hello, Alice, Bob, Carol!` for multiple names (comma-joined).
- `node greet.js --help` prints a single usage line and nothing else.
- `README.md` documents the exact output for all four invocation cases.
- `node check.js` gives you a dependency-free way to verify the CLI's output contract yourself.
- A separately-tested `src/greet-lib.ts` formatting module ships as groundwork for future CLI work (not used by `greet.js` yet).

### Try it
```
node greet.js
node greet.js Alice
node greet.js Alice Bob Carol
node greet.js --help
node check.js
```

See `README.md` in this release for the exact expected output of every case.

## Highlights

- First release: `node greet.js` greets no/one/multiple names and supports `--help`, exactly as documented in README.md.
- Dependency-free `check.js` guards the CLI's exact-stdout contract without needing the Vitest suite.
- README.md documents the precise expected output for all four invocation shapes plus how to self-verify them.
- New `src/greet-lib.ts` module ships a Vitest-tested `greeting()` formatter (serial/Oxford comma) as groundwork for a future CLI modularization — not yet used by greet.js.
- Minimal Node+TypeScript scaffolding added (package.json, tsconfig.json, vitest.config.ts, eslint.config.js, .prettierrc.json) with no CLI-only dependencies.

### Added

- `check.js`: dependency-free self-check script (built-in Node modules only — assert/child_process/process) that runs `greet.js` for the no-name, one-name, two-name, and `--help` cases, compares actual stdout to the exact expected output for each, prints which case failed and exits non-zero on any mismatch, and prints success and exits 0 when all four pass. (#304)
- README section documenting the four `check.js`-covered cases (exact command + exact expected output per case) and stating `node check.js` is how to verify them. (#304)
- `src/greet-lib.ts`: standalone, pure `greeting(names: string[]): string` formatter — 0 names -> `"Hello, World!"`, 1 -> `"Hello, Alice!"`, 2 -> `"Hello, Alice and Bob!"` (no comma), 3+ -> serial/Oxford-comma joined (e.g. `"Hello, Alice, Bob, and Carol!"`). Does no argv parsing, `--help` handling, or process I/O. Not yet imported by `greet.js`. (#302)
- `src/greet-lib.test.ts`: Vitest unit tests for `greeting()` covering the 0/1/2/3/4-name cases. (#302)
- Minimal Node+TypeScript project scaffolding: `package.json` (test/lint scripts), `tsconfig.json`, `vitest.config.ts`, `eslint.config.js`, `.prettierrc.json`, `.gitignore`. No CLI-only dependencies (no commander/yargs) and no `bin/` entry were added, per the groomed scope. (#302)
