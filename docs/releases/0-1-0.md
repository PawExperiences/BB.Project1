# e2e space invaders 0.1.0 (0.1.0)

## e2e space invaders v0.1.0

This is the inaugural release of **e2e Space Invaders** — a browser-based Space Invaders clone that runs directly from the filesystem with no build tooling, no bundler, and no server required. Simply open `index.html` in a modern browser (Chrome, Firefox, or Edge) via a `file://` URL and the game shell is live.

### Highlights

- **Game loop & canvas framework**: A robust fixed-timestep game loop (1/60 s steps, 250 ms delta cap) drives three scenes — Title, Playing, and Game Over — transitioning via ENTER with no page reload.
- **Shared constants**: All tunable values (`CANVAS_WIDTH`, `CANVAS_HEIGHT`, `PLAYER_SPEED`, `BULLET_SPEED`, `STARTING_LIVES`) are centralised in `gameConfig.js` and importable by any module.
- **HUD**: Score and lives are rendered directly on the canvas each frame in the Playing scene. The exported `hudState` object allows sibling modules to read and write game state.
- **Module scaffolding**: `input.js`, `player.js`, `invaders.js`, and `collision.js` are in place with their correct export shapes, ready for subsequent feature cards.
- **Zero dependencies**: No npm, no bundler, no CDN — pure ES modules loaded by the browser.

## Release steps

1. [manual] Verify CI build workflow currency - Open `.github/workflows/build.yml` and confirm it matches the toolchain this release ships: no bundler, no npm install step, artifact is the raw source files (index.html + *.js). If the build command or artifact_path in the BuildBoard build resource config has drifted from what the workflow contains, update the build resource config so BuildBoard re-scaffolds the workflow before tagging. This is a mandatory gate — CI must never drift from what we actually ship.
2. [manual] Confirm all source files are present on the target branch - On branch `main` (or the release branch), verify the following files exist at the repo root: `index.html`, `gameConfig.js`, `game.js`, `input.js`, `player.js`, `invaders.js`, `collision.js`, `README.md`. Run: `git ls-files index.html gameConfig.js game.js input.js player.js invaders.js collision.js README.md` — all eight paths must appear in the output.
3. [manual] Run manual acceptance verification (all ACs) - Open `index.html` via a `file://` URL in Chrome, Firefox, AND Edge. Step through every acceptance criterion:
1. 768×896 canvas on dark background, zero console errors.
2. Title scene shows 'SPACE INVADERS' (large, centred) + 'Press ENTER to start'.
3. ENTER transitions to Playing scene without page reload.
4. Playing scene clears canvas each frame; HUD shows score (top-left) and lives (top-right).
5. In the browser console, trigger game-over transition; confirm 'GAME OVER', current score, and 'Press ENTER to restart' appear.
6. ENTER on Game Over returns to Title without page reload.
7. In console: `import('./gameConfig.js').then(m => console.log(m))` — confirm all five constants.
8. Suspend tab for 3+ seconds; confirm no burst of catch-up updates on return.
9. Confirm `hudState` is readable from the console.
10. Confirm stubs exist: `import('./input.js').then(m=>console.log(m))` etc. for all four stub modules.
Record pass/fail for each AC before proceeding.
4. [automated] Create and push the release tag v0.1.0 - Run the release script (see scripts section). It will: (a) ensure the working tree is clean, (b) create an annotated git tag `v0.1.0` with message 'Release v0.1.0 — Game loop and canvas framework', (c) push the tag to origin. Command equivalent:
```
git tag -a v0.1.0 -m "Release v0.1.0 — Game loop and canvas framework"
git push origin v0.1.0
```
Do NOT force-push or delete any existing tag.
5. [automated] Package the release artifact (zip of source files) - Bundle the following files into `e2e-space-invaders-0.1.0.zip` (no subdirectory nesting — files at zip root): `index.html`, `gameConfig.js`, `game.js`, `input.js`, `player.js`, `invaders.js`, `collision.js`, `README.md`. The release script handles this. Exclude `.github/`, `test/`, `.git/`, and any editor config files.
6. [manual] Publish GitHub Release and upload artifact - On GitHub, navigate to the repository → Releases → 'Draft a new release'. Select tag `v0.1.0`. Set title: `e2e Space Invaders v0.1.0`. Paste the release notes from the `releaseNotes` field of this runbook into the body. Upload `e2e-space-invaders-0.1.0.zip` as the release asset. Check 'Set as latest release'. Publish. Do NOT mark as pre-release.
7. [manual] Verify published release on GitHub - After publishing: (a) confirm the release page shows tag `v0.1.0`, the correct release notes, and the uploaded zip asset. (b) Download the zip, extract, open `index.html` via `file://`, and smoke-test the Title scene renders correctly. (c) Confirm the CI workflow run triggered by the tag push completed successfully (green) in the Actions tab.
8. [manual] Announce release to stakeholders - Notify the project team that v0.1.0 is live. Include the GitHub Release URL and the single-step usage instruction: download the zip, extract, open index.html — no install needed.

## Rollback

1. Because this is the first release (no previous tag exists), a rollback means removing the shipped state from users' browsers — there is no prior version to revert to.
2. If the release tag `v0.1.0` was pushed and a regression is discovered: open a hotfix branch (`hotfix/0.1.1`), apply the minimal fix, run through the manual verification steps in README.md, and ship `v0.1.1`.
3. If the GitHub Release was published with a bad artifact: edit the GitHub Release page manually (do NOT delete it), uncheck 'Set as latest release', upload a corrected artifact, and update the release body with an errata notice.
4. Do NOT delete the `v0.1.0` tag or release — add a successor release instead.
