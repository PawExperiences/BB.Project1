# e2e calculator 0.1.0 (0.1.0)

## e2e calculator 0.1.0

This is the first public release of the **e2e calculator**, a self-contained Java 21 Swing desktop calculator packaged as a single executable JAR. Starting from an empty repository, this release delivers the complete foundation: a Maven project skeleton, a pure-Java expression evaluator with a full JUnit 5 test suite, a Swing graphical interface, and a runnable-JAR packaging configuration — all wired together so that a single `mvn -B package` produces `target/calculator-0.1.0.jar` and a `java -jar` invocation opens the calculator window.

### Highlights
- 🆕 **Maven skeleton** with Java 21 and JUnit Jupiter 5.10.2 — `mvn -B test` passes on a clean clone.
- 🧮 **Expression evaluator** (`Evaluator.evaluate(String)`) — full arithmetic precedence, parentheses, unary minus, decimal literals; throws `CalculationException` on bad input; never returns `NaN` or `Infinity`.
- 🧪 **Comprehensive unit tests** (`EvaluatorTest`) covering precedence, nesting, edge cases, and error paths.
- 🖥️ **Swing calculator window** — 320×420 px, full button grid, keyboard shortcuts (`Enter`, `Escape`, `Backspace`), clean error display.
- 📦 **Runnable JAR** — `java -jar target/calculator-0.1.0.jar` launches the GUI with no additional dependencies beyond JDK 21.
- ✅ **CI workflow** managed by BuildBoard ensures every push is verified.

### Added
- **Maven project skeleton** (`pom.xml`): `groupId=com.buildboard`, `artifactId=calculator`, `version=0.1.0`, Java 21 via `maven-compiler-plugin`, JUnit Jupiter 5.10.2 (test scope), `maven-surefire-plugin` 3.2.5.
- **Placeholder smoke test** (`src/test/java/com/buildboard/calculator/SkeletonTest.java`): single `@Test` asserting `assertTrue(true)` — confirms `mvn -B test` passes on a clean checkout.
- **Expression evaluator** (`src/main/java/com/buildboard/calculator/Evaluator.java`): pure-Java recursive-descent parser supporting `+`, `-`, `*`, `/`, operator precedence, parentheses to arbitrary depth, decimal literals, leading and post-operator unary minus, insignificant whitespace.
- **Checked exception** (`src/main/java/com/buildboard/calculator/CalculationException.java`): extends `Exception`, carries a descriptive message; thrown on division-by-zero and malformed input; no `NaN`/`Infinity` is ever returned.
- **Evaluator test suite** (`src/test/java/com/buildboard/calculator/EvaluatorTest.java`): covers precedence, nested parentheses, decimals, unary minus (leading and post-operator), division-by-zero, unbalanced parentheses, empty string, whitespace insignificance.
- **Swing calculator window** (`src/main/java/com/buildboard/calculator/CalculatorWindow.java`): `JFrame` (title `"Calculator"`, 320×420 px, not resizable); right-aligned non-editable `JTextField` display; full button grid (`0`–`9`, `.`, `+`, `-`, `*`, `/`, `(`, `)`, `C`, `=`); keyboard mapping (`Enter`=evaluate, `Escape`=clear, `Backspace`=delete-last); result formatted to ≤10 significant digits with no trailing zeros; error message shown on `CalculationException` with fresh-expression-on-next-keystroke behaviour.
- **Application entry point** (`src/main/java/com/buildboard/calculator/Main.java`): launches `CalculatorWindow` on the Swing EDT via `SwingUtilities.invokeLater`.
- **Runnable JAR packaging** (`pom.xml` updated): `maven-jar-plugin` sets `Main-Class: com.buildboard.calculator.Main`; final artifact `target/calculator-0.1.0.jar`.
- **README.md**: project purpose, build/run instructions (`mvn -B test`, `mvn -B package`, `java -jar target/calculator-0.1.0.jar`), planned file layout, confirmation that all tests pass during package.
- **CI build workflow** (`.github/workflows/build.yml`): BuildBoard-managed workflow scaffolded for this project.

[manual] Confirm CI workflow currency (.github/workflows/build.yml) - Open `.github/workflows/build.yml` and verify: (a) the build command is `mvn -B package`, (b) the artifact path is `target/calculator-0.1.0.jar`, (c) the Java version is `21`. 4. [automated] Run full build and test suite locally / on CI runner - Execute: `mvn -B clean package` from the repository root. Expected: exit code 0, all JUnit 5 tests green (SkeletonTest + EvaluatorTest), artifact `target/calculator-0.1.0.jar` present. Command: `mvn -B clean package && echo BUILD_OK`
5. [automated] Verify JAR manifest Main-Class - Run: `unzip -p target/calculator-0.1.0.jar META-INF/MANIFEST.MF | grep Main-Class`. Expected output: `Main-Class: com.buildboard.calculator.Main`. Fail the release if the entry is absent or incorrect.
6. [manual] Smoke-test the runnable JAR - On a machine with JDK 21, run: `java -jar target/calculator-0.1.0.jar`. Manually verify: (1) the window opens with title 'Calculator' at 320×420 px; (2) entering `2+3*4` and pressing Enter shows `14`; (3) entering `1/0` shows a non-blank error message; (4) pressing Escape clears the display; (5) Backspace removes the last character. Record the result.
7. [automated] Create and push the release tag v0.1.0 - Run the release script (see scripts section): `python release/scripts/release.py` (or `.sh` / `.ps1` equivalent). This script creates an annotated git tag `v0.1.0`, pushes it to origin, and prints the tag SHA. Confirm the tag appears at https://github.com/PawExperiences/BB.Project1/tags.
8. [manual] Create GitHub Release and upload JAR asset - Navigate to https://github.com/PawExperiences/BB.Project1/releases/new. Select tag `v0.1.0`. Set release title to `e2e calculator 0.1.0`. Paste the contents of the releaseNotes field as the release body. Upload `target/calculator-0.1.0.jar` as the binary asset. Mark as latest release. Publish.

[manual] Post-release verification - Confirm: (1) https://github.com/PawExperiences/BB.Project1/releases shows `v0.1.0` as latest; (2) the JAR asset is downloadable; (3) downloading and running `java -jar calculator-0.1.0.jar` works from the release asset URL; (4) `.github/workflows/build.yml` still passes on `main` after the tag push.

## Rollback

1. This is the initial release (no prior version exists); a full rollback means removing the release and reverting consumers to building from source.
2. Delete the GitHub Release `v0.1.0` (UI: Releases → Edit → Delete release) — this removes the release page and attached JAR asset but does NOT delete the tag.
3. To stop the tag from being used: communicate to consumers that `v0.1.0` is retracted; do NOT force-delete the tag from the remote (protected remote state rule).
4. If a hotfix is needed instead of a full retraction, branch from `v0.1.0`, apply the fix, and release `v0.1.1` following the same runbook.
5. For any running instances: the application has no persistent state, no database, and no server process — stopping the JVM process is sufficient. No data migration or schema rollback is required.
