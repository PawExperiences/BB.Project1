# e2e space invaders 0.1.0 (0.1.0)

## e2e Space Invaders v0.1.0

This is the inaugural release of **e2e Space Invaders** — a complete, browser-native Space Invaders clone built entirely with vanilla HTML5 Canvas and ES modules. The game requires no build step, no npm install, and no local server: open `index.html` directly from your filesystem and play.

### Highlights
- **Full four-level campaign**: Classic invader grid (Level 1) → faster grid with enemy fire and a skill-tested UFO (Level 2) → destructible shield bunkers and a mid-level formation split (Level 3) → multi-phase boss finale with a Win Screen (Level 4).
- **Polished game loop**: Fixed 60 Hz timestep with a 250 ms delta cap, scene state machine (Title / Playing / Game Over), and a canvas-drawn HUD showing score, hi-score, and lives.
- **Zero dependencies**: Pure HTML5 Canvas + ES modules. Works from `file://` on any modern browser.
- **Green CI**: GitHub Actions workflow validates the static artifact and packages it for release — no spurious npm failures.

# Changelog

## [0.1.0] - Initial Release

### Added
- `index.html`: Minimal HTML5 document with a 768×896 px canvas, dark background, opens from `file://` with no server required.
- `gameConfig.js`: ES module exporting `CANVAS_WIDTH=768`, `CANVAS_HEIGHT=896`, `PLAYER_SPEED=200`, `BULLET_SPEED=500`, `STARTING_LIVES=3`.
- `game.js`: Fixed-timestep game loop (60 Hz, ≤250 ms delta cap), scene state machine (Title → Playing → Game Over), HUD drawn on canvas, exports `hudState { score, lives, hiScore }`.
- `input.js`: ES module exporting `initInput()` and `isKeyHeld(code)` using `KeyboardEvent.code`; key-repeat-safe.
- `player.js`: `Player` class with `update(dt)` / `draw(ctx)` / `getBounds()`; clamped movement, single-in-flight bullet, procedural ship sprite.
- `formation.js`: Shared 11×5 grid layout constants (cell dimensions, invader types, initial positions).
- `invaders.js`: `InvaderGrid` class — 11×5 formation, step-and-drop movement, per-invader `alive` flag and `getBounds()`.
- `collision.js`: `CollisionSystem` class — AABB bullet-vs-invader and invader-bullet-vs-player checks, explosion effect rendering, `getScore()`.
- `state.js`: Shared session state (`sessionShotCount`, `lives`) imported by Levels 1 and 2.
- `level1.js`: Level 1 — classic 55-invader grid, linearly-scaled step interval (800 ms → 100 ms), breach detection, life loss, calls `game.nextLevel()` on clear.
- `level2.js`: Level 2 — 1.5× faster formation, invader shooting (random 800–2000 ms interval, lowest-alive-in-column fires, 300 px/s), player respawn with 2 s invulnerability and flash, UFO every 20 s (alternating sides, 120 px/s, tier scoring from `sessionShotCount`).
- `level3.js`: Level 3 — four destructible 4×4 bunkers at ~80% canvas height, formation split at 28th kill (columns 1–6 left, 7–11 right, independent sweep), transition to Boss on full clear.
- `boss.js`: Level 4 — 160×80 px canvas-primitive boss, horizontal drift at 90 px/s, 10 HP, Phase 1 (≥5 HP) fires 3-bullet spread every 1500 ms, Phase 2 (<5 HP) every 700 ms at 260 px/s, sudden-death on player hit resets to Level 1, Win Screen on 0 HP.
- `.github/workflows/build.yml`: Replaced broken npm-install workflow with a static-project-aware workflow: verifies `index.html` exists, packages static files as a release artifact, no `package.json` required.
- `README.md`: Added `## Planned File Layout` section listing all eight future module files with owning card names; added manual verification steps for all levels.

### Fixed
- CI workflow no longer attempts `npm install` / `yarn install` on a zero-dependency static project; build now passes green on every push.

## Release steps

1. [manual] Confirm CI workflow currency - Open `.github/workflows/build.yml` and verify it matches the static-project toolchain shipped in this release: no `npm install` / `yarn install` step, contains a step that checks for `index.html`, and uploads the static files as a workflow artifact. If it has drifted (e.g. someone added a build command or changed the artifact path), update the build resource config in BuildBoard so the workflow re-scaffolds before tagging.
2. [automated] Verify all required source files are present in the repository - Run the release script (`release/scripts/release.py` / `.sh` / `.ps1`) with the `--check-only` flag, or manually confirm the following files exist at the repo root: `index.html`, `game.js`, `gameConfig.js`, `input.js`, `player.js`, `formation.js`, `invaders.js`, `collision.js`, `state.js`, `level1.js`, `level2.js`, `level3.js`, `boss.js`, `.github/workflows/build.yml`, `README.md`. The release script will exit non-zero if any are missing.
3. [manual] Run a final smoke test in the browser - Open `index.html` directly via a `file://` URL (no server). Cycle through all four levels using the manual verification steps listed in `manualSteps`. Confirm no console errors. Sign off in the release checklist.
4. [automated] Create and push the release tag - Run: `git tag -a v0.1.0 -m 'Release v0.1.0 — initial release'` then `git push origin v0.1.0`. The tag must point to commit `0deb39d` (the HEAD of the merged boss-level PR). Do NOT force-push or delete any existing tags.
5. [manual] Confirm CI workflow run triggered by the tag is green - Navigate to https://github.com/PawExperiences/BB.Project1/actions and confirm the workflow run triggered by the `v0.1.0` tag completes with status 'success'. All steps — file-existence check, artifact packaging, and release upload — must be green. If any step fails, do not proceed to the GitHub Release step.
6. [automated] Create the GitHub Release - The CI workflow uploads the artifact automatically. Additionally, create the GitHub Release via the API or UI: tag `v0.1.0`, title `e2e Space Invaders v0.1.0`, body = the releaseNotes markdown above. Attach the packaged static artifact (zip of all game files) produced by CI. Do not mark it as a pre-release.
7. [manual] Post-release verification - Confirm the GitHub Release page at https://github.com/PawExperiences/BB.Project1/releases/tag/v0.1.0 shows the correct title, body, and downloadable artifact. Download the artifact, unzip, open `index.html` from `file://`, and confirm the game loads correctly.

## Rollback

1. Because this is the initial release (no previous tag), there is no earlier game version to roll back to at the code level.
2. If the GitHub Release artifact or tag must be retracted: DO NOT delete the tag or release via the GitHub UI or API (protected remote state). Instead, open a manual issue or contact the repository admin to assess the need; a human must decide and act.
3. To stop serving the game: remove the deployed static files from the hosting location (e.g. GitHub Pages branch or CDN) — this is a hosting action, not a git-history action, and is safe to perform.
4. To disable CI artifact publishing: edit `.github/workflows/build.yml` to comment out the upload-artifact / create-release steps and open a PR; merge it.
5. If a hotfix is needed, branch from `main` at commit `0deb39d`, apply the fix, and release as `0.1.1`.
