# e2e badge maker 0.1.0 (0.1.0)

## badge-maker 0.1.0

First public release of **badge-maker**, a small TypeScript library that renders shields.io-style status badges as self-contained SVG. This release ships the core `badge()` rendering function, the `textWidth`/`colourFor` helpers it's built on, and a documented, copy-pasteable Usage example.

### Highlights
- `badge(label, message, colour?)` renders a rounded, two-tone SVG badge (label in `#555`, message in `colour` or the default `#4c1`), with safe `&`/`<`/`>` escaping.
- Badge sizing and colour lookups live in one place -- `src/measure.ts` (`textWidth`, `colourFor`) -- backed by unit tests.
- README now has a Usage section with three worked examples and the exact SVG output of the first one, reproducible via `npm run example`.
- Fully typed build: `npm ci && npm run build` emits `dist/index.js` and `dist/index.d.ts`.

### Install
```
npm install badge-maker
```

### Quick start
```ts
import { badge } from "badge-maker";

console.log(badge("build", "passing"));
```


## Highlights

- First release: `badge()` renders a self-contained, rounded-corner SVG status badge from a label, message, and optional colour.
- Text width and colour-name lookups are centralized in `src/measure.ts` (`textWidth`, `colourFor`), unit-tested with Vitest.
- `&`, `<`, `>` in label/message text are escaped before embedding, so untrusted badge text can't break the SVG.
- README ships a Usage section with three worked examples plus the literal SVG output of the first one, kept honest by `npm run example`.
- Typed build pipeline: `npm ci && npm run build` (TypeScript ^5.4, ES2022/NodeNext) emits `dist/index.js` + `dist/index.d.ts`.

## [0.1.0] - 2026-08-11

### Added
- `badge(label, message, colour?)` in `src/index.ts`: renders a self-contained SVG status badge -- 20px tall, rounded corners, `#555`-filled label half, colour-filled message half (default `#4c1`) -- with `&`, `<`, `>` escaped to `&amp;`, `&lt;`, `&gt;` in embedded text. Each half is sized 6.5px per character plus 10px padding. (#231)
- `src/measure.ts`: single source of truth for badge sizing/colour -- `textWidth(s)` (`6.5 * s.length + 20`) and `colourFor(name)` (`green`->`#97ca00`, `yellow`->`#dfb317`, `red`->`#e05d44`, `grey`->`#9f9f9f`, else `#4c1`) -- with a Vitest suite in `src/measure.test.ts`. `src/index.ts` imports both instead of computing them inline. (#230)
- Project scaffolding: `package.json` (`badge-maker` v0.1.0, `"type": "module"`, `build` script running `tsc`, `typescript: "^5.4"` as the sole devDependency), `tsconfig.json` (`target: ES2022`, `module: NodeNext`, `outDir: dist`, `rootDir: src`, `declaration: true`), and the generated `package-lock.json`.
- README `Usage` section with three worked examples (default badge, custom colour, custom width) and the literal SVG markup produced by the first example, plus a new `npm run example` script that prints that same badge's SVG to stdout so the doc and the code stay in sync. (#232)
- Documented build commands: `npm ci && npm run build` produces `dist/index.js` and `dist/index.d.ts`.

## Rollback

This is the initial 0.1.0 release, so there is no prior version to fall back to, and remote deletions (tags, GitHub Releases, published npm versions) are forbidden. If a defect surfaces after shipping: (1) do NOT delete the `v0.1.0` tag, the GitHub Release, or any published npm version; (2) if `npm publish` already ran, run `npm deprecate badge-maker@0.1.0 "<reason>; use 0.1.1+"` to warn consumers without removing the package; (3) edit (never delete) the GitHub Release to add a warning note pointing at the fix; (4) fix forward by reverting the offending commit(s) on `main` with a new commit (no history rewrite), then cut 0.1.1 through this same runbook. If the defect is caught after tagging but before `npm publish`, simply skip the npm-publish step and ship the fix as 0.1.1 -- the existing tag and GitHub Release can stand as historical record.
