# e2e quote page 0.1.0

The first release of the e2e quote page: a minimal, zero-JS Astro static site that shows one hand-picked quote per build, styled for a dark screen and a clean printed page.

## Highlights
- Renders one of five curated quotes, centered, with the author credited beneath in smaller, dimmer type, on a dark background using only the system font stack.
- Quote selection is deterministic: `src/lib/pick.ts` seeds off the build date, so a given build always shows the same quote — no client-side JavaScript or randomness involved.
- Ships with zero runtime JavaScript and zero external network calls (no font providers, no fetches) — the page is static HTML/CSS end to end.
- A dedicated print stylesheet (`src/styles/print.css`) switches the page to black-on-white 12pt serif for printing without hiding any content.
- README documents `npm ci && npm run build` (output: `dist/index.html`) and how to add a new quote.

Install and build with `npm ci && npm run build`; the static site is written to `dist/index.html`.

## Changelog

## [0.1.0] - 2026-08-11

### Added
- Astro static site scaffold (`package.json`, `astro.config.mjs` with `output: "static"`) with a `build` script that runs `astro build`.
- Home page (`src/pages/index.astro`) rendering one of five quotes chosen at build time: quote text centered, author credited beneath in smaller, dimmer type, on a dark background using only the system font stack — zero runtime JS, no network calls.
- Quotes dataset (`src/data/quotes.json`): exactly 5 `{ text, author }` entries.
- Deterministic quote picker (`src/lib/pick.ts`): `pick<T>(items, seed)` returns the same item for the same seed across runs/processes; the home page seeds it with the build date so a given build's quote is reproducible, not random.
- Print stylesheet (`src/styles/print.css`), linked with `media="print"`: black text on a white background, 12pt serif body copy, no content hidden.
- `README.md`: install/build usage (`npm ci && npm run build` -> `dist/index.html`) and how to add a new quote via `src/data/quotes.json`.

This is the first release (no previous version) — everything above is new.

## Rollback

This is the first release (v0.1.0), so there is no prior version to fall back to and the site is static with no data/schema state — rollback is fix-forward, not deletion.
1. Never delete or force-push over the v0.1.0 tag, the GitHub Release, or any branch/PR created by this release (protected remote state) — rewrite nothing, only add.
2. If a defect is found post-release, edit the existing GitHub Release in place (`gh release edit v0.1.0`) to prepend a short 'Known issue' note pointing at the fix in progress, rather than removing or unpublishing it.
3. If the built site is deployed to static hosting, use that host's own 'redeploy previous deployment' control (there is no prior deployment for v0.1.0, so this applies starting with v0.1.1); do not touch this repo's git history to achieve it.
4. Cut a normal patch release (v0.1.1) containing the fix via the same release/scripts/release.* script — new tag, new GitHub Release, dist artifact rebuilt from the fixed commit.
5. No data or schema migrations shipped in this release, so there is nothing to reverse on that front.
