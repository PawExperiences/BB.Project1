# e2e space invaders 0.1.0 (0.1.0)

## e2e Space Invaders v0.1.0

This is the first public release of **e2e Space Invaders** — a fully playable, browser-based clone of the arcade classic built entirely with vanilla ES modules and the HTML5 Canvas API. No bundler, no npm, no server required: just open `index.html` from a `file://` URL in any modern browser and start playing.

### Highlights

- **Complete four-level run**: Classic invader grid (Level 1) → invaders shoot back with UFO bonus (Level 2) → destructible shields and split formation (Level 3) → two-phase boss fight finale.
- **Solid game engine**: Fixed-timestep loop at 60 Hz with delta capping, clean `update` / `render` separation, and a three-scene state machine (`title` → `playing` → `gameover`).
- **Procedural graphics only**: Every sprite — player ship, invaders, boss, HUD, health bar — is drawn with Canvas 2D primitives. Zero external image assets.
- **Progressive difficulty**: Speed scaling, enemy return fire, invulnerability windows, destructible cover, and a sudden-death boss phase create a genuine difficulty ramp across all four stages.
- **Shared, importable architecture**: `gameConfig.js` constants, `hudState` export, `rectsOverlap()` helper, and per-level lifecycle hooks are all reusable entry points for future cards.
- **CI note**: The previous `build.yml` workflow was removed in this cycle. The workflow must be re-scaffolded via the BuildBoard build resource config before merging to a protected branch.

# Changelog

## [0.1.0] - Initial Release

### Added
- **`index.html`** — Single-page host; 768×896 `<canvas>` centred on a dark background, loads `game.js` as an ES module. Works from a `file://` URL with no server.
- **`gameConfig.js`** — Shared constants: `CANVAS_WIDTH=768`, `CANVAS_HEIGHT=896`, `PLAYER_SPEED=200`, `BULLET_SPEED=500`, `STARTING_LIVES=3`.
- **`game.js`** — Main entry point: fixed-timestep loop (60 Hz, delta capped at 250 ms), `update(dt)` / `render()` phases, three-scene state machine (`title` → `playing` → `gameover`), ENTER-key transitions, canvas-drawn HUD (score / lives / hi-score), exported `hudState` named export.
- **`input.js`** — Keyboard-state module: `initInput()` attaches `keydown`/`keyup` listeners; `isKeyHeld(code)` returns current hold state; ignores `event.repeat` to suppress browser key-repeat.
- **`player.js`** — `Player` class: procedurally drawn ship (arcs + rects, no assets), delta-time movement (ArrowLeft/KeyA, ArrowRight/KeyD) with edge clamping, single-bullet firing (Space), bullet expiry at canvas top.
- **`invaders.js`** — 11×5 invader formation: lime-green `fillRect` sprites, horizontal sweep, edge-triggered drop (24 px) + direction reversal, bounding box shrinks with kills.
- **`collision.js`** — `rectsOverlap(a, b)` pure AABB helper (exported); `runCollisionPass()` orchestrating bullet-vs-invader checks, bullet deactivation, score increment, explosion spawn.
- **`explosion.js`** — `spawnExplosion(x, y)`, `updateExplosions()`, `drawExplosions(ctx)`: 8–12-frame flash effect at kill site.
- **`level1.js`** — Classic 11×5 grid; step-interval scales linearly 800 ms → 100 ms as invaders die; fires `onPlayerReached()` when formation reaches player row; fires `onLevelComplete(2)` on clear; re-initialisable.
- **`level2.js`** — Extends `Level` from `level1.js`; formation 1.5× faster (interval × 0.67); invaders fire downward at 300 px/s (random column, random 800–2000 ms interval); player hit → 1 life deducted, 2 s invulnerability + ship flash; UFO every 20 s alternating sides at 120 px/s, score tier keyed on `totalShotsFiredByPlayer % 4` → [50, 100, 150, 300].
- **`level3.js`** — Exports `start(canvas, ctx, onComplete)`; Level 2 mechanics inherited; four destructible 4×4-cell shield bunkers at y≈80% canvas height; formation split at 28 kills into two independent left/right groups sweeping full canvas width.
- **`boss.js`** — Multi-phase boss: canvas-primitive drawing, horizontal sweep, health bar (10 HP); Phase 1 (HP 10–6) fires at ~1 shot/1.5 s; Phase 2 (HP ≤5) fires at ~1 shot/0.6 s; sudden-death on hit (restart to Level 1, score reset); win screen on defeat showing final score and restart prompt.
- **`README.md`** — Repo root documentation: planned file layout, manual verification steps for all levels.

## Release steps

1. [manual] Verify CI workflow currency (build.yml) - The diffstat shows `.github/workflows/build.yml` was removed (86 lines deleted) in this release cycle. If the workflow is missing or stale, update the build resource `command` and `artifact_path` fields in BuildBoard so the workflow is regenerated, then commit the new `build.yml` to the release branch. A missing workflow means CI will not run on the tag.
2. [manual] Ensure release branch is up to date - Checkout the target branch (e.g. `main`): `git checkout main && git pull origin main`. Confirm the HEAD commit is `df0356c` (boss level merge) or later. Verify `git status` is clean.
3. [manual] Run manual smoke-test checklist - Follow all items in manualSteps above. Open `index.html` from a `file://` URL. Step through all four levels at least once, checking each acceptance criterion. Record any failures as blockers before proceeding.
4. [manual] Confirm all acceptance criteria are met - Review each bundled task's AC list against the diffstat. Every file listed in the diffstat (boss.js, collision.js, explosion.js, game.js, gameConfig.js, index.html, input.js, invaders.js, level1.js, level2.js, level3.js, player.js, README.md) must be present on the branch. 6. [manual] Create GitHub Release from tag - In the GitHub UI (or via `gh release create v0.1.0`), create a new Release pointing at tag `v0.1.0`. Paste the releaseNotes markdown as the release body. If the workflow is absent (due to the build.yml removal), stop here, re-scaffold via BuildBoard build resource config, and re-tag as `v0.1.0` only after confirming CI is green — consult a human maintainer if the tag was already pushed.
8. [manual] Post-release smoke test - Download the published artifact / checkout the tagged commit and repeat the critical path from manualSteps: title screen → Level 1 clear → Level 2 → Level 3 → boss defeat → win screen. Confirm the published release body is readable on GitHub.

## Rollback

Because this is the initial release (no previous version), a traditional rollback to a prior tag is not applicable. If a critical defect is found post-publish:
1. **Unpublish / yank the GitHub Release** via the GitHub Releases UI (edit the release and convert it back to a draft, or delete only the release record — do NOT delete the tag or commits).
2. Create a hotfix branch from the `0.1.0` tag: `git checkout -b hotfix/0.1.x v0.1.0`.
3. Apply the minimal fix, increment the patch version to `0.1.1`, and go through the full release process again.
4. Do not force-push, delete tags, or rewrite history on any remote branch.
