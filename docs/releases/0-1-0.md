# e2e space invaders 0.1.0 (0.1.0)

## e2e space invaders v0.1.0

This is the **first playable release** of *e2e Space Invaders* — a complete, five-stage browser game implemented as plain ES modules runnable directly from the filesystem (no build step, no server, no npm required). Open `index.html` in a modern browser and play.

### Highlights
- A full game loop with Title, Playing, and Game Over scenes
- A controllable player ship with keyboard input and single-bullet shooting
- A classic 11×5 invader formation with march, edge-drop, and AABB collision
- Three progressively harder levels (static grid → enemy fire + UFO → shields + split formation)
- A multi-phase boss fight with a health bar, phase transition, and a win screen
- Everything runs from a `file://` URL with zero dependencies

## Highlights

- First fully playable end-to-end Space Invaders game — Title → Level 1 → Level 2 → Level 3 → Boss → Win screen
- Fixed-timestep game loop (60 fps, delta-capped) with a three-scene state machine and canvas-drawn HUD
- Classic 11×5 invader grid with AABB collision detection, explosion effects, and score tracking
- Level 2 introduces enemy fire, UFO bonus rounds with shot-count-based scoring tiers, and player invulnerability on respawn
- Level 3 adds four destructible shield bunkers and a mid-level formation split into two independent halves
- Multi-phase boss fight with a live health bar, phase-triggered fire rate increase, sudden-death rule, and a congratulatory win screen

# Changelog

## [0.1.0] - Initial Release

### Added
- **Game loop and canvas framework** (`index.html`, `game.js`, `gameConfig.js`): 768×896 canvas on a black background, fixed-timestep game loop at 60 fps (delta capped at 0.25 s), scene state machine (Title → Playing → Game Over), canvas-drawn HUD (score, lives, hi-score), exported `hudState` object for downstream modules, stub comments for future imports.
- **Keyboard input and player ship** (`input.js`, `player.js`): `initInput()` / `isKeyHeld()` input manager using `keydown`/`keyup` listeners; `Player` class with delta-time movement at 200 px/s, edge clamping, single-bullet-in-flight shooting at 500 px/s, procedural ship and bullet drawing, `lives` counter seeded from `STARTING_LIVES`.
- **Sprite rendering and collision detection** (`invaders.js`, `collisions.js`, `explosions.js`): 11×5 invader grid (24×16 px cells, 8 px gaps), formation march (8 px/step, every 30 ticks), edge-drop (16 px) with direction reversal, AABB bullet-vs-invader collision pass (runs before draw), 8-frame explosion flash, on-canvas score display (+10 per kill), commented stub for future invader-bullet-vs-player collision.
- **Level 1: the classic grid** (`level1.js`): formation top at y=48 px, linear step-interval scaling (800 ms at 55 alive → 100 ms at 1 alive), one-cell-height drop on edge contact, win → transition to Level 2, lose life + formation reset when formation reaches player row, HUD level label.
- **Level 2: they shoot back** (`level2.js`): 1.5× faster formation (0.67× interval), global enemy shoot timer (800–2000 ms random), lowest-per-column invader fires at 300 px/s, UFO every 20 s alternating sides at 120 px/s, UFO score tiers based on `totalShotsFired % 4` (50/100/150/300), player hit → 2 s invulnerability with ship flash, standard game-over on last life.
- **Level 3: shields and splitting formation** (`level3.js`): four destructible shield bunkers at ~80% canvas height (4×4 grid of 8×8 px green cells), per-cell projectile erosion, formation split at ⌊startingCount/2⌋ kills into two independent sub-formations moving in opposite directions, independent edge-drop and invader fire per half, transition to boss on all-clear.
- **Boss level: multi-phase finale** (`boss.js`): boss drawn with canvas primitives, 10 HP, horizontal wall-bounce movement, Phase 1 (HP 10–6, fires every ~2 s), Phase 2 (HP ≤5, fires every ~1 s, health bar colour shift), 100 pts per hit + 500 pt completion bonus, sudden-death on boss bullet hit (Level 1 restart + score reset), win screen with final score and restart prompt.
- **Project README** (`README.md`): planned file layout, manual verification checklist for all levels and mechanics.

## Helper scripts (committed under release/scripts/)

- **release** `release/scripts/release.py` (python) -- Packages all game source files into a versioned zip artifact at release/e2e-space-invaders-0.1.0.zip. Run this after all feature branches are merged to main and the tag v0.1.0 has been pushed, as the final step before uploading to GitHub Releases.
- **release** `release/scripts/release.sh` (sh) -- Packages all game source files into a versioned zip artifact at release/e2e-space-invaders-0.1.0.zip. Run from the repository root after tagging v0.1.0. Requires zip (POSIX). Idempotent: re-running overwrites the zip.
- **release** `release/scripts/release.ps1` (powershell) -- Packages all game source files into a versioned zip artifact at release/e2e-space-invaders-0.1.0.zip. Run from the repository root after tagging v0.1.0. Idempotent: re-running overwrites the zip. Requires PowerShell 5+ (uses Compress-Archive).
- **run** `release/scripts/run.py` (python) -- Starts a minimal local HTTP server on port 8080 serving the repository root, then opens index.html in the default browser. Run from the repository root at any time to play the game via http:// (useful for browsers that restrict ES modules on file:// URLs, such as Safari). Does NOT modify any source files.
- **run** `release/scripts/run.sh` (sh) -- Starts a minimal local HTTP server on port 8080 serving the repository root, then opens index.html in the default browser. Run from the repository root at any time to play the game via http://. Requires Python 3 (uses http.server). Ctrl-C to stop.
- **run** `release/scripts/run.ps1` (powershell) -- Starts a minimal local HTTP server on port 8080 serving the repository root, then opens index.html in the default browser. Run from the repository root at any time to play the game via http://. Requires Python 3 on PATH. Ctrl-C to stop.

## Rollback

1. Because this is the initial release (no previous tag), a rollback means removing the v0.1.0 GitHub Release and its uploaded artifact so users stop downloading it.
2. Do NOT delete the tag or any commits — per protected-remote-state policy, history must not be rewritten.
3. On GitHub: navigate to Releases → v0.1.0 → Edit release → check 'Set as a pre-release' (or unpublish/draft) to hide it from the default releases page without destroying the tag.
4. Communicate to any users who downloaded the artifact that the release has been pulled and provide the previous known-good state (in this case: no prior release, so direct users to clone the repository at the last stable commit hash).
5. If a hotfix is needed, cut a v0.1.1 patch release from a fix branch; do not force-push or alter v0.1.0.
