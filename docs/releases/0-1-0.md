# mdpdf 0.1.0

The first release of **mdpdf** - a small, dependency-free Python CLI that turns a supported subset of Markdown into a single, self-contained HTML document styled for printing, so you can produce a clean PDF straight from your browser's Print dialog. No PDF library, no server, no external dependencies - just the Python standard library.

## Highlights
- `mdpdf IN.md -o OUT.html` writes a complete, print-ready HTML document; `mdpdf IN.md` (no `-o`) streams the same document to stdout.
- Supports ATX headings, paragraphs, **bold**/*italic*, inline code, fenced code blocks, unordered/ordered lists, and `[text](url)` links.
- Ships an embedded print stylesheet: A4 page geometry, 11pt serif body text, shaded monospace code, and orphan-heading protection (`page-break-after: avoid`).
- Includes `sample.md` so you can see every supported construct rendered at once - open the generated HTML in a browser and use Print -> Save as PDF.
- Missing input files fail loudly: `mdpdf MISSING.md` exits with status 2 and names the missing path.

## Install
```
pip install mdpdf
```

## Usage
```
mdpdf notes.md -o notes.html   # write to a file
mdpdf notes.md > notes.html    # write to stdout
```
Then open the HTML in a browser and choose Print -> Save as PDF.

# Changelog

## [0.1.0] - 2026-08-11

### Added
- `mdpdf` command-line tool: a dependency-free Python package that converts a supported subset of Markdown into a single, self-contained, print-styled HTML document (`mdpdf IN.md -o OUT.html`, or stdout via `mdpdf IN.md`).
- Markdown inline parser (`src/mdpdf/inline.py`, `render_inline`): bold (`**text**`/`__text__`), italic (`*text*`/`_text_`), inline code (`` `code` ``, not itself inline-parsed), and `[text](url)` links, with HTML-escaping of stray `&`, `<`, `>`.
- Markdown block parser (`src/mdpdf/blocks.py`, `render_blocks`): ATX headings, paragraphs, unordered (`-`/`*`/`+`) and ordered (`1.`) lists, and fenced code blocks (content emitted verbatim, not inline-parsed, HTML-escaped).
- Print stylesheet (`src/mdpdf/print.css`): `@page` sized for A4 with 2cm margins, an 11pt serif body, monospace code on a light (`#f5f5f5`) background, and `page-break-after: avoid` on heading levels so headings aren't orphaned when printed.
- `sample.md`: a demonstration document exercising the supported constructs, used to visually smoke-test `print.css` and the pipeline end-to-end.
- `README.md`: install instructions, both CLI usage forms (file output and stdout), and a section on producing a PDF via a browser's Print -> Save as PDF using `print.css`.
- `pyproject.toml`: packages the tool as `mdpdf` 0.1.0 with a `[project.scripts]` entry so `mdpdf` is on PATH after install.

## Rollback

This is the first tagged release, so there is no prior version to fall back to and no data/schema state to migrate back. If a defect is found after publishing: (1) Do NOT delete or force-push the v0.1.0 tag or the GitHub release - remote deletions and history rewrites are forbidden, and the tag/release must remain as an accurate historical record. (2) Edit the existing v0.1.0 GitHub release notes in place to add a visible notice pointing users at the fix (e.g. 'Known issue - see v0.1.1'). (3) Cut a corrective 0.1.1 patch release through the normal process once the fix is groomed and merged. (4) For local installs, `pip uninstall mdpdf` removes the CLI; there is no server or database component to roll back.
