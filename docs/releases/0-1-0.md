# e2e csv cleaner 0.1.0 (0.1.0)

## csvclean 0.1.0

The first release of **csvclean** — a small, dependency-free command-line tool for cleaning whitespace-dirty CSV files. Point it at a CSV and it strips stray leading/trailing whitespace from every data-row field, drops rows that are entirely empty once trimmed, and leaves the header exactly as it found it.

### Highlights
- Install with `pip install -e .` (from source) and get a `csvclean` command on your PATH.
- `csvclean IN.csv -o OUT.csv` writes the cleaned file; omit `-o` to stream the cleaned CSV to stdout for piping into other tools.
- A concise summary (rows read / rows dropped / fields trimmed) is printed to stderr on every run, so stdout stays pipeline-clean.
- Missing input file -> exit code 2 with a message naming the path; a successful run -> exit code 0.
- The cleaning rules (`clean_row`, `is_blank`) live in one module, `csvclean.rules`, and are covered by a pytest suite exercising padded headers, blank lines, whitespace-only rows, and RFC-4180 quoted commas.

### Getting started
```
pip install -e .
csvclean messy.csv -o clean.csv
```

No configuration and no runtime dependencies beyond the Python standard library.

## Changelog

## [0.1.0] - 2026-08-11
### Added
- `csvclean` CLI command (`csvclean IN.csv -o OUT.csv`) that strips leading/trailing whitespace from every field of every data row, leaves the header row byte-for-byte unchanged, and drops any data row that is entirely empty after trimming.
- Output to a file via `-o OUT.csv`, or to stdout when `-o` is omitted (with only the CSV on stdout — the run summary goes to stderr).
- Per-run summary on stderr: rows read, rows dropped, fields trimmed. Exit code 2 (naming the missing path) when the input file does not exist; exit code 0 on success.
- `src/csvclean/rules.py` — the single authoritative module exposing `clean_row(row)` and `is_blank(row)`, imported by both the CLI and the test suite instead of being re-implemented in each.
- `pyproject.toml` packaging: project name `csvclean`, version `0.1.0`, `requires-python = ">=3.12"`, and a `[project.scripts]` entry point so `pip install -e .` (or a built wheel) puts `csvclean` on PATH. `python -m build` produces a wheel and sdist.
- `tests/test_rules.py` plus `tests/fixtures/messy.csv` (and `tests/conftest.py`) — a pytest regression suite covering a whitespace-padded header, a fully blank row, a whitespace-only row, and an RFC-4180 quoted field with an embedded comma.
- `README.md` documenting install and usage.

## Rollback

0.1.0 is the first published version of csvclean, so there is no earlier release to fall back to. If a defect surfaces after publishing:
1. Do NOT delete or force-push over the `v0.1.0` tag or the GitHub release — tag/history deletion and force-push are forbidden.
2. Edit the existing v0.1.0 GitHub release (additive) to mark it 'Set as a pre-release' and add a note at the top of the release body pointing to the fix, so it no longer reads as production-ready.
3. Consumers who already installed 0.1.0 should `pip uninstall csvclean`, or pin to a known-good commit, until a patched release ships — there is no prior version to downgrade to.
4. Fix forward: land the fix, bump to 0.1.1, and re-run this same runbook to publish 0.1.1. Never overwrite or reuse the 0.1.0 tag or its artifacts.
5. If 0.1.0 was also published to a package index that supports yanking (e.g. PyPI), yank the 0.1.0 file there — index-level yank hides it from default installs without deleting anything from git or GitHub.
