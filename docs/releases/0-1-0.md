# e2e cli greeter 0.1.0 (0.1.0)

## e2e cli greeter v0.1.0

First release of the CLI greeter: a tiny, dependency-free Node.js command-line tool that prints a greeting for zero, one, or many names, backed by a pure unit-tested greeting-text module and a self-check script that proves the documented behaviour actually holds.

### Highlights
- `node greet.js` greets the world, one name, or a joined list of names, and `node greet.js --help` prints a one-line usage summary.
- Greeting-sentence formatting now lives in its own pure, unit-tested module, `src/greet-lib.ts`, separate from CLI argument handling.
- `node check.js` is a zero-dependency script that verifies all four documented CLI behaviours in one shot and fails loudly if any of them drift.
- `README.md` documents every case with the exact command and exact expected output, so behaviour can be verified without reading the source.
- This is the first release of the project - no upgrade or migration steps apply.

### Known follow-up
The "greet" ticket specifies `greet.js` joins two or more names with a plain `, ` (e.g. `Hello, Alice, Bob!`), while the "Greeting logic in its own file" ticket specifies `src/greet-lib.ts`'s `greeting()` joins the same names with "and"/an Oxford comma (e.g. `Hello, Alice and Bob!`). We could not confirm from the diff alone whether `greet.js` calls into `greet-lib` or keeps its own inline formatting, so we're not asserting a single unified behaviour here. See the release runbook's manual verification step before treating this as settled.

## Changelog

## [0.1.0] - 2026-08-15

First release. No previous version to diff against, so everything below is new.

### Added
- `greet.js` - minimal Node.js CLI greeter run as `node greet.js [names...]`. No arguments prints `Hello, world!`; one name prints `Hello, NAME!`; two or more names are joined with `, ` (e.g. `node greet.js Alice Bob` -> `Hello, Alice, Bob!`); `--help` prints exactly one usage line and exits 0. Plain JavaScript, manual `process.argv` handling, no CLI-parsing dependency (commander/yargs). (#321)
- `src/greet-lib.ts` - standalone `greeting(names: string[]): string` module extracted from the CLI so the sentence-building logic is independently unit-testable: `greeting([])` -> `"Hello, World!"`, `greeting(["Alice"])` -> `"Hello, Alice!"`, `greeting(["Alice","Bob"])` -> `"Hello, Alice and Bob!"`, 3+ names use an Oxford comma (`"Hello, Alice, Bob, and Carol!"`). Pure function, no argv/process I/O. Covered by `src/greet-lib.test.ts`. (#320)
- `check.js` - dependency-free Node self-check that exercises the CLI's four documented behaviours (no name, one name, two names, `--help`), prints per-case pass/fail, and exits non-zero the moment any case's actual output stops matching the expected output. (#322)
- `README.md` - documents all four CLI cases with the literal command and literal expected output, and tells the reader `node check.js` is how to verify them. (#321, expanded in #322)
- Project toolchain scaffolding for the TypeScript module: `package.json`, `package-lock.json`, `tsconfig.json` (first introduction of a build/test toolchain in this repo; `greet.js` and `check.js` remain plain, unbuilt Node scripts). (#320)

## Rollback

This is the first tagged release, so there is no prior version to fall back to. If a defect surfaces after shipping: (1) never delete or force-push the v0.1.0 tag or GitHub release -- that violates the project's no-destructive-remote-state policy; (2) fix forward with a normal commit (`git revert <bad-commit>` or a new fix commit) on main, run the same verification suite, and cut v0.1.1 through release/scripts/release.{sh,py,ps1}; (3) if v0.1.0 must be visibly retracted in the meantime, edit the existing GitHub release description to add a 'Known issue -- see v0.1.1' note and optionally mark it 'pre-release' in the GitHub UI -- both are edits, not deletions; (4) since greet.js and check.js are invoked directly with `node` and nothing else in the repo depends on this package yet, no consumer redeploy or data rollback is needed beyond re-pulling main.
