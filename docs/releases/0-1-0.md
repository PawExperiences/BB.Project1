# e2e gate check 0.1.0 (0.1.0)

factorlib 0.1.0 is the first release of a small, fully typed Python library for prime factorization, together with a ready-to-use command-line tool. Install it and either call `prime_factors()` from Python or run `factorlib <int> [<int> ...]` from your terminal to get instant factorizations.

**Highlights**
- New `factorlib.prime_factors(n)` API: trial-division prime factorization, returning the ascending-order multiset of prime factors for any integer `n >= 1` (`prime_factors(1) == []`), with clear `ValueError`/`TypeError` contracts for invalid input.
- New `factorlib` CLI: `factorlib 12 17` prints `12: 2 x 2 x 3` and `17: 17`, one line per integer.
- Fail-fast CLI error handling: stops on the first bad integer, reports to stderr, exits 1; exits 0 only when every input succeeds.
- Fully typed (`py.typed`), `src/`-layout package built with setuptools, targeting Python >=3.12.
- Complete automated test coverage for both the library and the CLI (`pytest` green, `ruff` clean).

## Highlights

- New `factorlib.prime_factors(n)`: trial-division prime factorization (2, then odd numbers up to sqrt(n)) returning the ascending-order multiset of prime factors.
- New `factorlib` command-line tool - run `factorlib 12 17` to print one `N: p1 x p2 x ... x pk` line per integer.
- Fail-fast CLI: stops immediately on the first integer that errors, prints the error to stderr, and exits 1; exits 0 only when every integer succeeds.
- Clear input contract: `prime_factors(1) == []`, `n <= 0` raises `ValueError` naming the offending value, non-int input raises `TypeError`.
- Typed, installable package (`py.typed`, `src/` layout, setuptools, Python >=3.12) with a green `pytest` + `ruff` suite covering both the library and the CLI.

### Added
- `factorlib` Python package: `src/`-layout, setuptools build backend, `requires-python = ">=3.12"`, shipped with a `py.typed` marker for downstream type-checking.
- `factorlib.prime_factors(n: int) -> list[int]` (`src/factorlib/factor.py`): trial division by 2 then odd divisors up to `sqrt(n)`. For `n >= 2` returns the ascending-order multiset of prime factors (e.g. `prime_factors(12) == [2, 2, 3]`, `prime_factors(97) == [97]`, `prime_factors(49) == [7, 7]`); `prime_factors(1) == []`; raises `ValueError` (naming the offending value) for `n <= 0`; raises `TypeError` for non-int input. Exported from `src/factorlib/__init__.py` as `from factorlib import prime_factors`.
- `factorlib` command-line front end (`src/factorlib/cli.py`) registered as a console script in `pyproject.toml`: `factorlib <int> [<int> ...]` prints one `N: p1 x p2 x ... x pk` line per integer, in the order given; fails fast on the first integer that errors (no output for remaining integers, error to stderr, exit code 1); exit code 0 when all integers succeed.
- Test suite: `tests/test_factor.py` (composite/prime/prime-square/1/0/negative/non-int cases) and `tests/test_cli.py` (multi-integer success formatting, fail-fast stderr/exit-1 behavior, exit-0 on full success).

## Rollback

This is the initial 0.1.0 release, so there is no prior version to fall back to. If a defect is found after shipping: (1) never delete or force-push the v0.1.0 git tag, the GitHub release, or any published package artifact. (2) If already published to PyPI, use PyPI's 'yank' feature on the 0.1.0 file (hides it from default installs without deleting it) rather than removing the release. (3) Fix forward: branch from v0.1.0, apply the fix, and cut 0.1.1 through the same release process (release/scripts/release.*). (4) If the GitHub release needs to be flagged, edit its description to add a visible 'known issue, superseded by v0.1.1' note instead of deleting or unpublishing it.
