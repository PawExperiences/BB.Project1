# e2e space invaders 0.1.0 (0.1.0)

## e2e space invaders v0.1.0

This is the **initial release** of *e2e Space Invaders* — a browser-based Space Invaders clone built entirely with vanilla ES modules and no external dependencies. This release establishes the complete game scaffold: an HTML canvas host, a fixed-timestep game loop, a three-scene state machine (Title → Playing → Game Over), shared configuration constants, and a HUD rendering system with exportable state. All code runs directly from a `file://` URL in Chrome or Firefox with no build step required.

### Highlights
- 🎮 **Game Loop & Canvas Framework** — 60-updates/s fixed-timestep loop with 250 ms delta cap; no burst updates after backgrounding the tab.
- 🖼️ **Three-Scene State Machine** — Title, Playing, and Game Over scenes with ENTER-key transitions; full in-memory reset, no page reload.
- 📊 **HUD & Shared State** — `drawHUD()` renders score and lives on the canvas; `hudState` is a live named export any sibling module can read and mutate.
- ⚙️ **Shared Constants** — `gameConfig.js` is the single source of truth for canvas dimensions, speeds, and starting lives.
- 📄 **Developer README** — Module map and manual verification checklist for opening `index.html` directly in a browser.
- 🤖 **CI Workflow** — BuildBoard-scaffolded `.github/workflows/build.yml` tracks the project build resource.

[manual] Verify CI workflow currency - Open `.github/workflows/build.yml` and confirm the `build` job's command and artifact path match the toolchain this release ships (vanilla HTML/JS, no build step). 5. [automated] Package release artifact (zip of source) - Zip the project files (index.html, game.js, gameConfig.js, input.js, player.js, invaders.js, collision.js, README.md) into `e2e-space-invaders-0.1.0.zip`. Performed by the release script.

## Rollback

This is the initial release (no previous version). Rollback procedure:
1. Delete the GitHub release and tag `v0.1.0` via the GitHub UI (Releases → Delete release; Tags → Delete tag).
2. If a Pages or static hosting deployment was made, revert to the previous deployment (or take the site offline) via the hosting console.
3. No database or schema migrations were applied in this release — no data rollback is required.
4. Locally, run `git checkout <sha-before-tag>` to return to the pre-release state.
