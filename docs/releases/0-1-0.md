# e2e gate check 0.1.0 (0.1.0)

## factorlib 0.1.0

First release of `factorlib`, a small, typed Python 3.12+ library for prime factorization, with a ready-to-use command-line front end. Install it and either `from factorlib import prime_factors` in your own code, or run `factorlib 12 18 7` straight from the shell to see each number's prime factors.

### Highlights
- Core API: `factorlib.prime_factors(n) -> list[int]` -- trial-division factorization with multiplicity, ascending order.
- Clear input contract: `TypeError` on non-int, `ValueError` (naming the value) on `n <= 0`, `[]` for `n == 1`.
- New `factorlib` CLI: `factorlib 12 18 7` prints one `n: p1 p2 p3` line per argument, fail-fast on the first bad input.
- Installable, typed package (`py.typed`) built with setuptools from a `src/` layout, `requires-python >= 3.12`.
- Full test coverage: composite, prime, prime-square, 1, 0, negative, and non-int inputs.

See the changelog for the full list of changes.

# Changelog

## [0.1.0] - 2026-08-11

### Added
- `factorlib` package skeleton: installable via `pyproject.toml` (setuptools build backend, `src/` layout, `requires-python = ">=3.12"`, and a `py.typed` marker shipped as package data for the typed-library contract).
- `factorlib.prime_factors(n: int) -> list[int]`: prime factorization by trial division (2, then odd numbers up to `sqrt(n)`), returning factors with multiplicity in ascending order (e.g. `prime_factors(12) == [2, 2, 3]`).
- Input contract for `prime_factors`: raises `TypeError` on non-int input; raises `ValueError` naming the offending value for `n <= 0`; returns `[]` for `n == 1` (no prime factors, by convention).
- `factorlib` console-script CLI (`src/factorlib/cli.py`, wired via `[project.scripts]`): `factorlib <n> [<n> ...]` prints one `n: p1 p2 p3` line per argument, in the order given; stops fail-fast on the first error (message to stderr, exit code 1) without discarding output already printed for prior arguments; exits 0 once all arguments succeed.
- Test suite (`tests/test_factor.py`) covering a composite (12), a prime (97), a prime square (49), 1, 0, a negative number, and a non-int input.

## Rollback

This release has no data/schema migrations and does not publish to PyPI, so rollback only concerns the git tag and the GitHub Release -- neither of which may be deleted (remote deletions are prohibited).

- If an issue is found BEFORE a human clicks Publish on the draft GitHub Release: simply do not publish. Fix the issue on a new commit and re-run release/scripts/release.{py,sh,ps1}; the script is idempotent about the tag (it skips re-tagging if v0.1.0 already exists locally) and will refresh the draft release's build artifacts.
- If an issue is found AFTER the release is published: do NOT delete the v0.1.0 tag or the GitHub Release. Instead: (1) edit the published release on GitHub and mark it as a pre-release with a note pointing at the issue; (2) cut a follow-up patch release (0.1.1) with the fix using this same runbook; (3) if the package is later published to a package index, use that index's yank/deprecate mechanism rather than deletion -- not applicable to this 0.1.0 release since it does not publish to PyPI.
