# e2e word count 0.1.0 (0.1.0)

## e2e word count v0.1.0

A small, dependency-free `wc`-style word-count CLI written in Go. Point it at one or more files (or pipe stdin) and it reports line, word, and byte counts per input, tab-separated, plus a summed `total` row when you give it more than one file. This is the project's first release.

### Highlights
- Counts lines (`\n` bytes), words (`bufio.ScanWords`-style maximal non-whitespace runs), and raw bytes for each named file or for stdin (shown as `-`).
- Multi-file runs get an extra `total` row summing each column across the files that were read successfully; single-input runs don't print one.
- A file that can't be opened is reported on stderr (`wordcount: <name>: <error>`) and skipped — the rest of the run continues; the process exits 1 if any file failed to open, 0 otherwise.
- Counting is isolated in `count.go` (`Counts{Lines, Words, Bytes}` + a reader-based counter), separated from CLI argument handling for testability, with no change to observable CLI output.
- Table-driven tests and a matching README table both cover empty input, a line with no trailing newline, runs of repeated whitespace, and multi-byte UTF-8 input.

### Getting it
Build from source with Go 1.22+:
```
go build -o wordcount ./...
./wordcount README.md go.mod
```

No breaking changes — this is v0.1.0. See CHANGELOG.md for the full list of changes.

## Changelog

## [0.1.0] - 2026-08-11

### Added
- Initial Go implementation of a `wc`-style word-count CLI (`go.mod` — module `wordcount`, go 1.22 — and `main.go`). Reads each file named on the command line, or stdin when none are given, and writes one line per input: `<lines>\t<words>\t<bytes>\t<name>` (`-` for stdin).
- `total` summary line printed after the per-file lines whenever more than one input is processed, summing lines/words/bytes across the files that were read successfully.
- Per-file error handling: a file that can't be opened is reported as `wordcount: <name>: <error>` on stderr and skipped, while the run continues; the process exits 1 if any named file failed to open, 0 otherwise.
- `README.md` describing the tool's usage and output format.
- Table-driven tests in `count_test.go` covering four cases: empty input, a line with no trailing newline, runs of consecutive whitespace, and multi-byte UTF-8 input.
- A README usage/output table documenting the exact command and exact output for each of those four test cases.

### Changed
- Counting logic moved out of `main.go` into a new `count.go`, behind an exported `Counts{Lines, Words, Bytes}` struct and an exported `io.Reader`-based counting function; `main.go` now only handles CLI argument/flag parsing and I/O wiring. Pure refactor — CLI output is unchanged for any given input.

### Fixed
- Nothing (first release; no fixes in this bundle).

## Rollback

This is the project's first release (v0.1.0) and ships a single self-contained CLI binary with no server, database, or persisted state to roll back in production.
1. Do NOT delete the v0.1.0 tag, the GitHub release, or any commits — remote deletions/history rewrites are forbidden. The tag and release stay in place as a permanent record.
2. Fix forward: branch from main, fix the defect, re-run the full check suite (gofmt/vet/build/test), and cut v0.1.1 via this same runbook/release script.
3. If v0.1.0 is actively misleading consumers (e.g. a broken binary), edit the existing GitHub release description in place to add a visible warning ('Known issue — see v0.1.1') and/or mark it as a pre-release via the GitHub UI. Both are in-place edits, not deletions.
4. Tell anyone who already pulled the v0.1.0 binary or built from that tag to update to v0.1.1 once it's published — there is no automatic rollback mechanism for a distributed CLI binary.
