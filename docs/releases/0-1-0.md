# e2e space invaders 0.1.0 (0.1.0)

## e2e Space Invaders v0.1.0

This is the first public release of **e2e Space Invaders** — a complete, browser-native Space Invaders clone that runs directly from a `file://` URL with zero build steps, zero npm dependencies, and zero external assets. Every sprite is drawn with Canvas 2D primitives.

### Highlights
- **Full game arc**: Title screen → Level 1 → Level 2 → Level 3 → Boss → Win screen, all wired together through a single fixed-timestep game loop.
- **Progressive difficulty**: formation speed accelerates as invaders are eliminated; Level 2 adds enemy fire and a bonus UFO; Level 3 introduces destructible shield bunkers and a dramatic formation split; the boss adds a two-phase fight with sudden-death stakes.
- **Zero friction to play**: clone the repo, open `index.html` in any modern browser — that's it.
- **Clean ES-module architecture**: eight focused modules (`gameConfig.js`, `game.js`, `input.js`, `player.js`, `invaders.js`, `collision.js`, `level1–3.js`, `boss.js`) with no circular dependencies and a shared `hudState` export for live HUD updates.
- **CI-verified**: a GitHub Actions build workflow lints/syntax-checks every commit.

## Highlights

- Complete 4-stage game arc: three invader levels plus a two-phase boss fight, all in a single `file://`-openable HTML page
- Fixed-timestep game loop (60 Hz) with background-tab delta cap, distinct update/render phases, and a scene state machine (TITLE / PLAYING / GAME_OVER)
- Progressive invader AI: speed curve from 800 ms → 100 ms per step, enemy bullets (Level 2+), destructible shield bunkers and formation split (Level 3)
- Bonus UFO in Level 2 with tiered scoring (50/100/150/300 pts) driven by player shot count
- Two-phase boss: visible health bar, fire-rate doubling at 5 HP, sudden-death one-hit-reset rule, and a dedicated win screen
- Zero external dependencies — pure ES modules, Canvas 2D primitives, opens from disk

# Changelog

## [0.1.0] - Initial Release

### Added
- **Game loop and canvas framework** (`index.html`, `game.js`, `gameConfig.js`, `README.md`): Fixed-timestep game loop at 60 Hz, scene state machine (TITLE → PLAYING → GAME_OVER), canvas HUD (score, lives, hi-score), shared constants module, exported `hudState` named export.
- **Keyboard input and player ship** (`input.js`, `player.js`): Held-key tracking via `initInput()`/`isKeyHeld()`, procedurally-drawn player ship, single-bullet firing with `BULLET_SPEED`, movement clamped to canvas bounds, `lives` property for level cards.
- **Sprite rendering and collision detection** (`invaders.js`, `collision.js`): 11×5 invader grid rendered as filled rectangles, step-and-drop formation movement, AABB bullet–invader collision pass, explosion flash effect (~300–500 ms), per-kill score increment via `POINTS_PER_KILL` constant.
- **Level 1 – The Classic Grid** (`level1.js`): `init/update/render` module interface, step-interval curve scaling linearly from 800 ms (55 invaders) to 100 ms (1 invader), edge-bounce-and-drop, loss condition at Y = 540 px with full formation reset, level-clear transition to Level 2, HUD level label.
- **Level 2 – They Shoot Back** (`level2.js`): 1.5× faster formation (0.67× intervals), randomised enemy shoot timer (800–2000 ms), lowest-column-invader firing at 300 px/s downward, UFO every 20 s alternating sides at 120 px/s with tiered score (50/100/150/300 pts keyed on `playerTotalShotCount % 4`), 2-second respawn invulnerability with visual flash.
- **Level 3 – Shields and Formations** (`level3.js`): Four destructible shield bunkers at ~80 % canvas height (4×4 cell grids, `#00FF41`), per-cell erosion by player and invader projectiles, formation split at 50 % kills into two independently-sweeping halves moving in opposite directions, advance to boss on full clear.
- **Boss Level – Multi-Phase Finale** (`boss.js`): Canvas-primitive boss entity with 10 HP and visible health bar, horizontal edge-bouncing movement, Phase 1 (HP 6–10, fires every 2 s) → Phase 2 (HP ≤ 5, fires every 1 s with visual change), sudden-death rule (one hit resets to Level 1), win screen with final score and restart.

## Release steps

1. [manual] Confirm CI build is green on release commit - Visit https://github.com/PawExperiences/BB.Project1/actions and verify the build workflow run for commit 03dfcea (or the HEAD of main) shows a green checkmark. Do not proceed if CI is red.
2. [manual] Verify .github/workflows/build.yml matches current toolchain - Open .github/workflows/build.yml and confirm the build command, Node version, and artifact path reflect the no-bundler, plain-ES-module toolchain shipped in this release. The project has no build step beyond a lint/syntax check, so the workflow should run a syntax/lint check (e.g. `node --check *.js`) and archive the source files as the artifact. If the workflow content has drifted, update the build resource config in BuildBoard so the workflow re-scaffolds — do NOT edit the workflow file directly outside BuildBoard's ownership.
3. [automated] Run syntax check on all JS modules locally - From the repo root, run: `node --check game.js gameConfig.js input.js player.js invaders.js collision.js level1.js level2.js level3.js boss.js`. All files must exit 0 with no output. This mirrors what CI does.
4. [manual] Manual smoke test in Chrome (file:// URL) - Open index.html via file:// in Chrome. Verify: (1) Title screen shows 'SPACE INVADERS' and 'Press ENTER to start'. (2) ENTER transitions to PLAYING with HUD score=0, lives=3, hiScore=0. (3) Invader grid visible, player ship moves/fires. (4) Check browser console — zero errors.
5. [manual] Manual smoke test in Firefox (file:// URL) - Repeat the smoke test in Firefox. ES module loading from file:// has stricter CORS handling in some Firefox versions; confirm no module-load errors.
6. [manual] Full playthrough verification - Play through Level 1 (clear all 55 invaders) → auto-transition to Level 2 (confirm faster formation and enemy bullets) → Level 2 clear → Level 3 (confirm shields at ~80% height, formation split at 50% kills) → Level 3 clear → Boss (confirm health bar, Phase 1 at 10–6 HP, Phase 2 at ≤5 HP with visual change) → Boss kill → Win screen with final score and restart option.
7. [automated] Create and push the v0.1.0 tag - Run the release script (see scripts section): `python release/scripts/release.py` or `sh release/scripts/release.sh` or `pwsh release/scripts/release.ps1`. The script will: (1) confirm the working tree is clean, (2) create annotated tag v0.1.0 with the release message, (3) push the tag to origin. Command equivalent: `git tag -a v0.1.0 -m 'Release v0.1.0 — e2e Space Invaders initial release' && git push origin v0.1.0`.
8. [automated] Package the release archive - Zip the following files from the repo root into `e2e-space-invaders-0.1.0.zip`: index.html, game.js, gameConfig.js, input.js, player.js, invaders.js, collision.js, level1.js, level2.js, level3.js, boss.js, README.md. Exclude .github/, test/, and any dot-files. The run script (release/scripts/run.*) shows users how to open the app after extracting.
9. [manual] Publish GitHub Release - Go to https://github.com/PawExperiences/BB.Project1/releases/new. Select tag v0.1.0. Set title to 'e2e Space Invaders v0.1.0'. Paste the release notes from this runbook into the body. Upload e2e-space-invaders-0.1.0.zip as the binary asset. Click 'Publish release'.
10. [manual] Post-release verification - After publishing: (1) Download the release archive from GitHub and confirm it extracts and opens correctly via file://. (2) Verify the release page renders the changelog correctly. (3) Confirm the v0.1.0 tag appears at https://github.com/PawExperiences/BB.Project1/tags.

## Rollback

1. Since this is the initial release (no previous version tag), a rollback means removing the v0.1.0 GitHub Release and its tag so the repository returns to an untagged state.
2. Navigate to https://github.com/PawExperiences/BB.Project1/releases, find the 'v0.1.0' release, click 'Delete release' (this does NOT delete the tag automatically).
3. Navigate to https://github.com/PawExperiences/BB.Project1/tags, find 'v0.1.0', and delete the tag.
4. For any users who downloaded the release archive: direct them to clone the repo at the commit they need (`git checkout <sha>`).
5. No database migrations were applied, so no data rollback is required.
6. No environment variables or secrets were added in this release, so no config rollback is needed.
