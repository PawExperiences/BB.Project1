# mdpdf 0.1.0

`mdpdf` is a new, dependency-light command-line tool that turns a constrained Markdown subset into a single, print-ready HTML document, so you can go from Markdown to a clean PDF using nothing more than your browser's built-in Print dialog. This is the first release of the project: the CLI, the parsing engine (`inline.py` / `blocks.py`), and a print-tuned stylesheet all ship together as one installable package.

## Highlights
- New `mdpdf` CLI: `mdpdf IN.md -o OUT.html` writes a file, `mdpdf IN.md` writes to stdout
- Supports headings, paragraphs, **bold**/*italic*, `inline code`, fenced code blocks, links, and ordered/unordered lists
- Dedicated `inline.py` and `blocks.py` parser modules with a typed, reusable representation of parsed Markdown
- Print CSS tuned for A4: serif 11pt body text, monospace code with a light background, and headings that are never orphaned at the bottom of a page (`page-break-after: avoid`)
- `sample.md` fixture and README instructions for producing a PDF via a browser's Print to PDF feature
- Missing input files fail fast with exit code 2 and a clear error naming the missing path

## Install
```
pip install dist/mdpdf-0.1.0-py3-none-any.whl
```
or from source:
```
pip install .
```

## Usage
```
mdpdf report.md -o report.html
# open report.html in a browser, then Print > Save as PDF
```

## Changelog

## [0.1.0] - 2026-08-11

### Added
- `mdpdf` command-line tool: converts a constrained Markdown subset into a single, print-ready HTML document (`pyproject.toml`, `src/mdpdf/__init__.py`, `src/mdpdf/cli.py`). `mdpdf IN.md -o OUT.html` writes a file; `mdpdf IN.md` (no `-o`) writes the document to stdout; `mdpdf MISSING.md` exits with status 2 and names the missing path.
- Core Markdown parsing layer: `src/mdpdf/inline.py` (plain text, bold, italic, inline code, links) and `src/mdpdf/blocks.py` (ATX headings, paragraphs, unordered/ordered list items, fenced code blocks with optional language tag), producing a typed representation that `cli.py` renders to HTML. Text inside fenced code blocks is preserved verbatim; `&`, `<`, `>` in ordinary text are entity-escaped.
- Print stylesheet `src/mdpdf/print.css`: `@page` sized for A4 with margins, 11pt serif body text, monospace code on a light background, and `page-break-after: avoid` on heading elements.
- `sample.md` fixture at the repo root exercising the supported Markdown syntax, used to visually verify the HTML/CSS output end-to-end.
- `README.md`: install instructions, both CLI invocation forms, and a section on producing a PDF via a browser's "Print to PDF" feature.
- Test suite: `tests/test_inline.py`, `tests/test_blocks.py`.

## Rollback

This is the initial 0.1.0 release, so there is no prior version to fall back to -- treat rollback as 'undo the publish, not delete it':
1. Do NOT delete the v0.1.0 git tag or the GitHub Release; deleting remote state is forbidden. Instead edit the release in place: `gh release edit v0.1.0 --notes-file <updated-notes>` to prepend a visible warning banner, and `gh release edit v0.1.0 --prerelease` to de-emphasize it without removing it.
2. If mdpdf is also published to a package index later, use that index's 'yank' mechanism (not delete) so `pip install mdpdf` stops resolving to the bad build by default while `pip install mdpdf==0.1.0` (explicit) still works for debugging.
3. Fix forward: branch from main, `git revert <sha>` the offending commit(s) (never rewrite history on main), run it through Grooming/Ready/.../Review as normal, and cut 0.1.1 through this same runbook.
4. Update the v0.1.0 GitHub Release notes to link forward to v0.1.1 once published.
5. No data/schema migrations exist in this release, so no migration rollback is required.
