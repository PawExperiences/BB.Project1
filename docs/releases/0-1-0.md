# e2e word count 0.1.0 (0.1.0)

## wordcount v0.1.0

First release of `wordcount`, a small Go CLI that reproduces the classic `wc -lwc` behaviour: point it at one or more files, or pipe input to it, and it reports lines, words, and bytes for each input plus a combined total when you give it more than one.

### Highlights
- Drop-in `wc -lwc`-style counting for files or stdin, with `-` used to label stdin in the output.
- Tab-separated `<lines>\t<words>\t<bytes>\t<name>` output per input, with an automatic `total` line across inputs when more than one is given.
- Per-file failures are reported on stderr (`wordcount: <name>: <error>`) without aborting the rest of the run; the process exits 1 only if at least one file failed.
- Counting logic lives in its own file (`count.go`) behind an exported, `io.Reader`-based API, independently unit tested.
- Table-driven tests and a matching README table lock down four tricky edge cases: empty input, missing trailing newline, repeated spaces, and multi-byte UTF-8 text.

### Getting it
Build from source with Go 1.22+: `go build -o wordcount .`, or grab the platform binary attached to this release.

## Changelog

## 0.1.0 - 2026-08-11

### Added
- Initial Go implementation of the `wordcount` CLI (`go.mod` declaring module `wordcount`, Go 1.22; `main.go`; `README.md`), matching classic `wc -lwc` behaviour: reads one or more files named on the command line, or stdin when none are given, and reports lines/words/bytes for each.
- Tab-separated output `<lines>\t<words>\t<bytes>\t<name>` per input, with stdin labelled `-`, and a summed `total` line when more than one input is given (omitted for a single input).
- Per-file error handling: an unreadable file is reported as `wordcount: <name>: <error>` on stderr, processing continues for the remaining inputs, and the process exits 1 if any file failed (0 if all succeeded).
- `count.go`: an exported `Counts` struct (lines/words/bytes) and an exported counting function operating on any `io.Reader`, independent of CLI/file-opening logic.
- `count_test.go`: table-driven tests for the counting logic covering four edge cases -- empty input, a single line with no trailing newline, a line with repeated/consecutive spaces, and input containing multi-byte UTF-8 characters (byte count vs. rune count).
- README usage table documenting the exact CLI output for those same four cases.

### Changed
- `main.go` reduced to argument parsing and I/O setup only; all line/word/byte counting logic moved to `count.go` (pure refactor, no behaviour change, verified by identical output before/after and by the new tests).

### Fixed
- N/A (first release).

## Rollback

This is the first tagged release, so there is no prior version to fall back to; "rollback" means containing the bad release, not restoring an older one. Do not delete or force-push the v0.1.0 tag, branch, or GitHub release -- that is forbidden destructive remote state. Instead: (1) edit the v0.1.0 GitHub release description to add a visible warning and mark it as a pre-release via `gh release edit v0.1.0 --prerelease`; (2) revert the offending commit(s) on `main` with `git revert` (never `reset --hard` or history rewrite) and open a PR; (3) cut a corrective v0.1.1 release through the normal release flow once the revert/fix lands, and point consumers at v0.1.1 in the release notes of v0.1.0. There are no data/schema migrations in this release, so no migration rollback is required.
