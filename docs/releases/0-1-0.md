# e2e space invaders 0.1.0 (0.1.0)

## e2e Space Invaders 0.1.0

This is the first public release of **e2e Space Invaders** — a complete, dependency-free, browser-native Space Invaders implementation built as vanilla ES modules that open straight from the filesystem (`file://`) in any modern browser. No bundler, no npm, no server required.

### Highlights
- A solid 60 Hz fixed-timestep game loop with delta capping so backgrounded tabs never burst.
- Three fully playable levels: the classic accelerating grid (Level 1), return fire + bonus UFO (Level 2), and destructible shield bunkers with a mid-level formation split (Level 3).
- Clean scene state machine (Title → Level 1 → Level 2 → Level 3 → Win / Game Over) with life and score persistence across levels.
- All rendering is pure Canvas 2D — no image assets, no external dependencies.
- A GitHub Actions CI pipeline (`.github/workflows/build.yml`) validates the build on every push.
- Ready-to-run helper scripts (`release/scripts/`) for tagging, publishing, and launching the game on Windows, macOS, and Linux.

# Changelog

## [0.1.0] - Initial Release

### Added
- **Game loop and canvas framework** (`index.html`, `game.js`, `gameConfig.js`): 768×896 canvas on a dark background, fixed-timestep loop at 60 Hz with delta cap, scene state machine (Title → Playing → Game Over), HUD rendering, and `switchScene` / `hud` exports.
- **Shared constants** (`gameConfig.js`): `CANVAS_WIDTH=768`, `CANVAS_HEIGHT=896`, `PLAYER_SPEED=200`, `BULLET_SPEED=500`, `STARTING_LIVES=3`, plus grid/cell sizing and scoring constants added by later cards.
- **Stub modules** (`input.js`, `player.js`, `invaders.js`, `collision.js`): correct exported names in place from day one so all sibling modules can import without errors.
- **Keyboard input** (`input.js`): `initInput()` attaches `keydown`/`keyup` listeners; `isKeyHeld(key)` returns live held-state (not key-repeat).
- **Player ship** (`player.js`): procedurally drawn ship (arcs + rectangles), delta-time-scaled movement at 200 px/s, canvas-edge clamping, single-bullet firing at 500 px/s, `lives` counter seeded from `STARTING_LIVES`.
- **Invader grid** (`invaders.js`): `InvaderGrid` class managing 11 × 5 = 55 invaders as filled rectangles; step-and-drop edge detection; configurable `speedMultiplier`; `allDefeated()` predicate.
- **Collision detection** (`collision.js`): AABB `checkBulletInvaderCollisions(bullet, grid)` and stub `checkInvaderBulletPlayerCollision`; collision pass guaranteed before render pass; `checkBulletBunkerCollisions` added for Level 3 shields.
- **Explosion effects**: brief canvas-only flash/expanding rectangle at destroyed-invader position (≤ 500 ms, configurable duration).
- **Level 1** (classic grid): step-interval scales linearly from ~800 ms (55 alive) to ~100 ms (1 alive); formation drops one cell height on edge hit; life loss + formation/player reset when formation reaches player row; win condition advances to Level 2; HUD shows level number.
- **Level 2** (they shoot back): `speedMultiplier 1.5`, lives/score carry over, `shotCount` resets to 0; random invader return fire at 180 px/s; player hit with 1-second death pause, respawn at default position, 2-second blink invulnerability window; bonus UFO with distinct ellipse/dome canvas drawing, random 15–30 s appearance interval, point tier based on `shotCount % 4` → {100, 50, 150, 300}; `shotCount` increments on every player shot; Level 2 clear shows static 'Level Complete' / 'You Win' screen.
- **Level 3** (shields and formations): four destructible 4×4 bunkers at ≈80 % canvas height, individual cell erosion by both player and invader bullets; formation split into independent left/right halves when ⌊startCount/2⌋ invaders destroyed, opposite initial directions; `InvaderGrid` extended/subclassed to support split; `allDefeated()` true only when both halves cleared; `checkBulletBunkerCollisions` in `collision.js`.
- **README.md**: full file-layout description, per-module one-liners, manual verification walkthrough covering all levels, shields, split, and collision.
- **CI workflow** (`.github/workflows/build.yml`): GitHub Actions pipeline scaffolded by BuildBoard; validates that `index.html` opens without errors (no bundler, no server).
- **Release helper scripts** (`release/scripts/release.{py,sh,ps1}`, `release/scripts/run.{py,sh,ps1}`).

## Release steps

1. [manual] Verify CI build passes on the release commit - Navigate to https://github.com/PawExperiences/BB.Project1/actions and confirm the latest run of `.github/workflows/build.yml` on the tip of `main` (commit 290dce5 or later) is green. Do not proceed if any job is failing.
2. [manual] Confirm CI workflow matches current toolchain - Open `.github/workflows/build.yml`. Verify: (a) no Node/npm/bundler steps are present; (b) the artifact upload step captures `index.html` and all sibling `.js` files (collision.js, game.js, gameConfig.js, input.js, invaders.js, player.js, shields.js) plus `README.md`; (c) any 'build command' in the BuildBoard build resource config is a no-op or a simple file-copy — no compile step. If any of these are wrong, update the BuildBoard build resource `command` and `artifact_path` fields so the workflow re-scaffolds correctly before tagging.
3. [automated] Create and push the release tag `v0.1.0` - Run: `git tag -a v0.1.0 -m 'Release 0.1.0 — e2e Space Invaders initial release' && git push origin v0.1.0`. This is performed by `release/scripts/release.{py,sh,ps1}`.
4. [automated] Package the release artifact ZIP - Collect: `index.html`, `game.js`, `gameConfig.js`, `input.js`, `player.js`, `invaders.js`, `collision.js`, `shields.js`, `README.md`. Zip them into `space-invaders-0.1.0.zip` (no subdirectory wrapper). Performed by the release script.
5. [automated] Create the GitHub release draft and upload artifact - Using the GitHub CLI: `gh release create v0.1.0 space-invaders-0.1.0.zip --title 'e2e Space Invaders 0.1.0' --notes-file release/notes-0.1.0.md --draft`. Performed by the release script. The `--draft` flag keeps it unpublished until human approval.
6. [automated] Write release notes file for the draft - The release script writes the `releaseNotes` content above to `release/notes-0.1.0.md` before calling `gh release create`.
7. [manual] Human review of the GitHub release draft - Open https://github.com/PawExperiences/BB.Project1/releases and review the draft: check title, tag, notes, and that the artifact ZIP is present and non-empty. Download and unzip the artifact; open `index.html` from the ZIP to confirm the game loads from `file://`.
8. [manual] Publish the GitHub release - Click 'Publish release' on the draft, or run: `gh release edit v0.1.0 --draft=false`. This makes the release publicly visible.
9. [manual] Post-release smoke test - Download the published artifact ZIP from the GitHub releases page, unzip, open `index.html` in Chrome and Firefox via `file://`, and walk through: Title → Level 1 → Level 2 → Level 3 → Win screen. Confirm no console errors at any point.
10. [manual] Update CHANGELOG.md on main - Prepend the changelog section for 0.1.0 (from this runbook) to `CHANGELOG.md` and open a PR to `main`. Do not commit directly to main.
11. [manual] Add docs/releases/0.1.0.md - Create `docs/releases/0.1.0.md` with the full release notes content from this runbook and open a PR to `main`.

## Rollback

1. This is the initial release (no previous tag). A rollback means reverting to an unplayable state, so the practical rollback is: (a) remove the GitHub release and its uploaded artifact, then (b) revert the merge commit on `main` with `git revert <merge-commit-sha> --no-edit` and push — this preserves history. No database or schema changes exist, so no data rollback is needed. (c) If the CI workflow was updated, revert `.github/workflows/build.yml` in the same revert commit. (d) Communicate to any players/testers that 0.1.0 has been pulled.
